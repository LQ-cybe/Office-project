# 多维表分析 — 桌面版独立软件设计方案

> 目标：在现有 Excel 插件（MultiTableAddin）基础上，孵化一款**独立桌面软件**，脱离对 Excel/WPS 超级表的运行时依赖，采用**独立数据库文件**承载多张数据表，并支持 **Excel 文件导入 / 导出**。
> 基线复用：v2.9.42 的视图体系、CSS Token、组件库、交互范式（详见《多维表插件UI布局与设计风格分析》）。
> 文档性质：需求与架构设计（非实现代码）。

---

## 一、设计目标

| # | 目标 | 说明 |
|---|---|---|
| G1 | 独立运行 | 无需安装 Office 即可启动；双击 .exe 打开主窗口 |
| G2 | 独立数据库文件 | 单个 `.mtdb`（SQLite）承载一个"工作区"的全部表/视图/配置；可复制/备份/邮件传输 |
| G3 | 多数据表组织 | 一个库内可建多张表（类比插件一个工作簿多张超级表），表间独立、视图各自绑定 |
| G4 | Excel 导入 | 从 `.xlsx` 导入为库内新表（首行表头→字段，区域→数据）；支持追加/覆盖模式 |
| G5 | Excel 导出 | 将库内表/视图结果导出为 `.xlsx`（保留字段类型、汇总、视图布局尽量还原） |
| G6 | 复用插件 UI | 视图框架（表格/表单/画册/日历/甘特/仪表盘/图表）、组件库、交互范式整体继承 |
| G7 | 平滑迁移 | 老用户可把既有 `.multiview.json` + Excel 数据一键导入新库 |

---

## 二、技术选型

| 层 | 选型 | 理由 |
|---|---|---|
| 运行时 | .NET 8（net8.0-windows） | 与插件同栈，复用 C# 数据引擎与类型 |
| UI 宿主 | WPF + WebView2（保留 `HtmlMainForm` 范式） | 前端继续用单文件 SPA（`index.html`），改动最小 |
| 前端 | 原生 HTML/CSS/JS（无框架） | 直接继承插件 `index.html` 的 CSS Token/组件/视图渲染 |
| 本地数据库 | **SQLite**（`Microsoft.Data.Sqlite` 或 `System.Data.SQLite`） | 单文件、零配置、跨平台、事务安全、足够支撑百万行级单表 |
| Excel I/O | **MiniExcel** 或 **ClosedXML** | MiniExcel 轻量低内存（流式）；ClosedXML 格式控制强（样式/合并/公式）。导入用 MiniExcel，导出可用 ClosedXML 还原样式 |
| 打包 | 单文件 EXE（self-contained + 单文件发布） | `dotnet publish -r win-x64 -c Release -p:PublishSingleFile=true --self-contained` |

> 选 SQLite 而非 JSON 文件：单表可至百万行级、支持索引/查询/事务，JSON 仅适合配置。**数据用 SQLite，视图/字段配置仍用 JSON 段（嵌入库内元数据表）**，分层存储。

## 三、数据库文件设计（`.mtdb`）

单个 `.mtdb` = 一个 SQLite 数据库文件，内含：

### 3.1 元数据表（系统表，前缀 `_mt_`）

```sql
-- 工作区元信息
CREATE TABLE _mt_workspace (
  id INTEGER PRIMARY KEY,
  name TEXT,            -- 工作区名（显示用）
  app_version TEXT,     -- 创建时的软件版本
  created_at TEXT,      -- ISO8601
  updated_at TEXT
);

-- 数据表登记（每张业务表一行）
CREATE TABLE _mt_tables (
  table_id TEXT PRIMARY KEY,        -- 如 t_1700000000_xk3
  name TEXT NOT NULL,                -- 逻辑表名（用户可改）
  source_file TEXT,                  -- 来源 Excel 文件名（导入留痕）
  source_sheet TEXT,
  row_count INTEGER DEFAULT 0,
  created_at TEXT,
  sort_order INTEGER DEFAULT 0
);

-- 字段定义
CREATE TABLE _mt_fields (
  table_id TEXT NOT NULL,
  field_id TEXT NOT NULL,
  name TEXT NOT NULL,                -- 字段名
  type TEXT NOT NULL,                -- Text/Number/Integer/Currency/Percentage/Select/Quarter/Date/DateTime/Image
  options TEXT,                      -- JSON：Select 选项、Number 精度等
  is_primary INTEGER DEFAULT 0,
  sort_order INTEGER DEFAULT 0,
  PRIMARY KEY(table_id, field_id)
);

-- 视图配置（每张表可多个视图）
CREATE TABLE _mt_views (
  view_id TEXT PRIMARY KEY,
  table_id TEXT NOT NULL,
  view_type TEXT NOT NULL,           -- Table/Form/Gallery/Calendar/Gantt/Dashboard/Chart
  view_name TEXT,
  user_view INTEGER DEFAULT 0,
  config TEXT,                       -- JSON：visibleFields/groupBy/cardMeta/calendarConfig/ganttConfig/dashboardConfig...
  sort_order INTEGER DEFAULT 0
);

-- 全局应用设置（对应插件 localStorage['mt_app_settings']）
CREATE TABLE _mt_settings (
  key TEXT PRIMARY KEY,
  value TEXT
);
```

### 3.2 业务数据表（每张表一张物理表，前缀 `t_`）

```sql
-- 每张逻辑表对应一张物理表，列=字段，行=记录
CREATE TABLE t_xxxxxxxx (
  _row_id INTEGER PRIMARY KEY AUTOINCREMENT,  -- 内部行号
  _created_at TEXT,
  _updated_at TEXT,
  <field_name> <sqlite_type>,                 -- 按字段类型映射
  ...
);
-- 对常用筛选/排序字段建索引
CREATE INDEX idx_t_xxxxxxxx_<field> ON t_xxxxxxxx(<field>);
```

字段类型映射：

| 插件 FieldType | SQLite 存储 |
|---|---|
| Text / Select / Quarter | TEXT |
| Number / Currency / Percentage | REAL |
| Integer | INTEGER |
| Date / DateTime | TEXT (ISO8601) |
| Image | TEXT（存图片文件相对路径或 base64） |

> 选 "每表一物理表" 而非 "EAV/JSON 列"：查询性能、SQL 语义清晰、导出直接 `SELECT *`。改字段结构时用 `ALTER TABLE`（SQLite 支持加列；删列/改类型用"重建表"标准流程）。

### 3.3 文件归属

- `.mtdb` 文件 = 全部数据 + 元数据 + 配置，**一个文件即一个工作区**。
- 图片资源（画册视图）：可选内嵌为 base64（小图）或同目录 `.<db名>.assets/` 文件夹（大图），库内只存相对引用。

## 四、整体架构

```
┌─────────────────────────────────────────────┐
│  WebView2 (index.html SPA)                  │  ← 复用插件前端（CSS Token/组件/视图渲染）
│  api.call(method, params) ──────────────┐   │
└──────────────────────────────────────────┘   │
                                               ▼
┌─────────────────────────────────────────────┐
│  桥接层 (MessageRouter)                      │  ← 复用插件 HtmlMainForm 的消息派发
│  listTables / openTable / saveConfig /       │
│  addField / updateRow / importExcel /        │
│  exportExcel / query ...                    │
└──────────────────┬──────────────────────────┘
                   ▼
┌─────────────────────────────────────────────┐
│  数据引擎 (DataAdapter)                      │  ← 新增：替换原 ExcelAdapter
│  ┌──────────┐  ┌────────────┐  ┌─────────┐  │
│  │ SQLite   │  │ Excel I/O  │  │ Schema │  │
│  │ Repo     │  │ (导入/导出)│  │ Migrator│  │
│  └──────────┘  └────────────┘  └─────────┘  │
└─────────────────────────────────────────────┘
                   ▼
            本地 .mtdb 文件
```

**与插件的关键差异**：仅替换"数据引擎"层——把 `ExcelAdapter`（读写 ListObject）换成 `SqliteAdapter`（读写 SQLite）+ `ExcelIoService`（导入导出 xlsx）。前端、桥接、视图逻辑几乎不动。

## 五、Excel 导入流程

```
用户：文件 → 导入 Excel → 选 .xlsx
  │
  ▼
1. MiniExcel 流式读取首 sheet（或用户指定 sheet/区域）
2. 首行作为表头 → 生成字段定义（类型自动识别：数字/日期/文本/单选候选）
   - 列全数字 → Number；列全日期 → DateTime；列唯一值≤12 → 建议 Select
3. 弹"导入预览"模态：确认表名 / 字段类型 / 导入模式（新建表 / 追加到现有表 / 覆盖现有表）
4. 事务写入：
   - 新建表：CREATE TABLE t_xxx + INSERT 批量（事务，失败回滚）
   - 追加：INSERT 到现有表（按字段名匹配，多余列忽略或新建字段）
   - 覆盖：DROP + CREATE + INSERT
5. 更新 _mt_tables / _mt_fields 元数据 + row_count
6. 生成默认视图集（复用插件 ViewConfigManager.CreateDefaultConfig 逻辑）
7. toast('已导入 N 行 × M 列'); 刷新侧栏表列表
```

要点：
- 大文件流式读取，避免一次性载入内存（MiniExcel 优势）。
- 类型识别复用插件现有 `FieldType` 推断逻辑。
- 导入失败整体回滚，不留半成品表。

## 六、Excel 导出流程

```
用户：表/视图 → 导出 Excel
  │
  ▼
1. 选导出范围：当前表全量 / 当前视图筛选结果 / 当前视图布局
2. 选导出模式：
   - 纯数据（字段+行，等同 ListObject）
   - 视图还原（表头样式 + 冻结 + 列宽 + 汇总行；画册分组导出为分组工作表；仪表盘导出图表为图片）
3. ClosedXML 构建 .xlsx：
   - 表头行加粗灰底 + 冻结首行
   - 列宽按视图 colWidths
   - 数字/日期列设置 NumberFormat
   - 视图筛选/排序结果按当前顺序写出
4. 弹保存对话框 → 写盘 → toast('已导出 path')
```

要点：
- 纯数据导出走 MiniExcel（快、省内存）；视图还原导出走 ClosedXML（样式可控）。
- 导出"画册分组"→每分组一个工作表或一列分块，参考飞书导出。

## 七、前端改动点（最小化）

继承 `index.html` 全部 CSS/组件/视图渲染，仅改数据接口与少量入口：

| 改动 | 位置 | 内容 |
|---|---|---|
| 数据源切换 | `listTables`/`openTable` 返回结构不变 | C# 侧从 SQLite 读，返回给 JS 的 `{tables, fields, rows, config}` 结构与插件一致 → **JS 几乎不动** |
| 新增菜单 | 顶部工具条或设置面板 | "导入 Excel…" / "导出 Excel…" / "新建数据表…" / "打开工作区" / "新建工作区" |
| 多表切换 | 侧栏 `.sidebar-top .table-select` | 已有下拉可直接复用（插件已支持多超级表切换） |
| 持久化 | `saveConfig` | C# 侧改为写 `_mt_views` 表，而非嵌入工作表 |
| 全局设置 | `localStorage` → `_mt_settings` | 跨设备随库走（可选项，也可仍用本地 localStorage） |

> 设计原则：**前端只感知"一张表有 fields/rows/views"的抽象，不关心数据来自 Excel 还是 SQLite**。因此视图层零改动。

## 八、C# 数据引擎接口（DataAdapter 抽象）

抽出一个接口，让 Excel 插件版与桌面版共用上层：

```csharp
public interface IDataAdapter
{
    List<TableInfo> ListTables();
    TableData OpenTable(string tableId);          // {sheet,table,fields,rows,config}
    void SaveConfig(string tableId, WorkbookConfig cfg);
    void AddField(string tableId, FieldDef field);
    void UpdateRow(string tableId, int rowId, Dictionary<string,object> values);
    int AddRow(string tableId, Dictionary<string,object> values);
    void DeleteRow(string tableId, int rowId);
    // Excel I/O（仅桌面版实现）
    ImportResult ImportExcel(string xlsxPath, ImportOptions opt);
    void ExportExcel(string tableId, ExportOptions opt, string outPath);
}
```

- 插件版：`ExcelDataAdapter`（实现 ListTables/OpenTable/...，Excel I/O 抛 NotSupported）。
- 桌面版：`SqliteDataAdapter`（全实现）。
- 上层 `MessageRouter` 只依赖接口，靠配置注入实现 → **未来还能加 CSV/JSON 适配器**。

## 九、从插件迁移（老用户路径）

1. 桌面版首启提供"从 Excel 工作簿导入"入口。
2. 读取该工作簿全部超级表 → 每张生成库内一张表（同 Excel 导入流程）。
3. 若同目录存在 `{filename}.multiview.json` 或工作表 `_MultiTableConfig` → 解析视图配置写入 `_mt_views`（`viewType=Kanban` 按 v2.9.40+ 规则迁移为 Gallery；看板视图类型已于 v2.9.42 移除）。
4. 字段类型按既有 `FieldOverrides` + 自动识别合并。
5. 完成后即可脱离原 Excel 文件独立运行；原文件不动。

## 十、交付与打包

- **发布命令**：`dotnet publish MultiTableDesktop -c Release -r win-x64 -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true --self-contained true`
- 产物：单文件 `多维表分析.exe`（含 .NET 运行时 + WebView2 固定版？WebView2 Runtime 仍需用户机器预装或捆绑安装器）。
- 关联文件扩展名：`.mtdb` 关联到本程序，双击即打开对应工作区。
- 图标：复用插件 `AppIcon.ico`（多尺寸 16~256），主窗+EXE 一致。

## 十一、里程碑（建议顺序）

| 阶段 | 产出 | 依赖 |
|---|---|---|
| M1 数据引擎 | `SqliteDataAdapter` + 元数据表 + 建表/改表/CRUD | 无 |
| M2 前端对接 | 侧栏多表切换 + "新建工作区/打开工作区"入口 | M1 |
| M3 Excel 导入 | MiniExcel 读取 + 类型识别 + 导入预览模态 | M1 |
| M4 Excel 导出 | ClosedXML 纯数据导出 + 视图还原导出 | M1 |
| M5 迁移工具 | 从 .xlsx + .multiview.json 一键迁库 | M3 |
| M6 打包 | 单文件 EXE + .mtdb 关联 + 安装器 | M1~M5 |

## 十二、与插件版的并存策略

- 插件版（Excel 内嵌）与桌面版（独立 .mtdb）**长期并存**：
  - 轻度用户/已在 Excel 工作流内的 → 继续用插件版。
  - 需要独立库/多库/离线/批量导入导出的 → 用桌面版。
- 二者共享 `IDataAdapter` 抽象与前端 `index.html`，**一套视图代码两套数据后端**，维护成本最低。
- 桌面版可视为插件版的"超集"（多了独立库与 Excel I/O），功能不回退。
