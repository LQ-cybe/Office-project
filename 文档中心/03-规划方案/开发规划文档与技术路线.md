# 多维表分析软件 — 独立桌面 EXE 开发规划与技术路线

> 文档版本：v1.0  
> 日期：2026-08-07  
> 定位：完全本地离线运行的 Windows 桌面独立 EXE，不依赖 Microsoft Office，不依赖网络

---

## 一、项目概述

### 1.1 产品目标

开发一款**独立桌面应用程序**，以本地 xlsx/csv 文件作为权威数据源，提供多维表式的多视图浏览与编辑能力。

核心能力对标飞书多维表的六大视图：

| 视图类型 | 说明 |
|---------|------|
| 表格视图 Table | 类 Excel 网格，支持列隐藏、排序、筛选 |
| 表单视图 Form | 单条记录弹窗编辑，按字段类型动态生成输入控件 |
| 看板视图 Kanban | 按字段分组，卡片可跨列拖拽，拖拽即改分组字段值 |
| 画册视图 Gallery | 流式卡片网格布局，图片优先展示 |
| 日历视图 Calendar | 按日期字段将记录渲染到日历格子 |
| 甘特视图 Gantt | 按起止时间字段绘制横向进度条，支持拖拽改时间 |

### 1.2 核心设计原则

1. **源文件权威**：xlsx/csv 是唯一业务数据源，所有编辑操作最终回写源文件
2. **视图配置分离**：视图的筛选、分组、排序、卡片布局等元配置存储在独立 JSON 文件中，不混入业务数据
3. **视图层只读变换**：过滤、分组、排序全部在内存完成，不修改磁盘上的原始数据排列
4. **单表多视图**：普通 xlsx/csv 是平面表，不支持飞书多维表的跨表关联、lookup、rollup；本软件只做单数据表多视图
5. **全离线**：无任何云端依赖，所有数据本地存储

### 1.3 约束与边界

| 能力 | 是否支持 | 原因 |
|------|---------|------|
| 单表多视图浏览编辑 | ✅ 支持 | 核心目标 |
| 看板拖拽改状态 | ✅ 支持 | 拖拽 → 修改字段值 → 回写源文件 |
| 甘特拖拽改日期 | ✅ 支持 | 拖拽 → 修改起止日期 → 回写源文件 |
| 跨表关联 / lookup / rollup | ❌ 不支持 | xlsx/csv 是平面表，无关系型能力 |
| 多选字段 / 公式字段 | ❌ 不支持 | 普通 Excel 无字段元信息 |
| 多人协同 | ❌ 不支持 | 本地单用户 |
| 保留 Excel 复杂样式 / 宏 / 图表 | ⚠️ 部分丢失 | 第三方库读写 xlsx 会丢失复杂格式 |

> **升级路径**：如后续需要完整多维表能力（跨表关联、公式字段），可将主存储切换为内置 SQLite（.mvt.db 文件），xlsx/csv 仅作导入导出交换格式。

## 二、技术路线对比与选型

### 2.1 三条可选技术路线总览

| 维度 | 路线 A：Electron + Vue3 | 路线 B：.NET WPF/Avalonia | 路线 C：.NET WinForms + WebView2 |
|------|------------------------|--------------------------|----------------------------------|
| 产出形态 | 独立 exe | 独立 exe | 独立 exe |
| 依赖 Office | ❌ 不需要 | ❌ 不需要 | ❌ 不需要 |
| UI 开发工作量 | **中等**（复用前端组件） | **很高**（全部自研） | **中等**（混合方案） |
| exe 体积 | 80-150 MB | 15-40 MB | 30-60 MB |
| 内存占用 | 较高（Chromium 内核） | 低 | 中等 |
| 看板拖拽组件 | ✅ 开箱即用（vue-kanban 等） | ❌ 全部自研 | ✅ 前端组件 |
| 甘特图组件 | ✅ 开源成熟（vue-gantt-task 等） | ❌ 全部自研 | ✅ 前端组件 |
| 画册卡片流式布局 | ✅ CSS 原生支持 | ⚠️ WrapPanel 需自研虚拟化 | ✅ 前端组件 |
| 日历组件 | ✅ FullCalendar 成熟 | ❌ 全部自研 | ✅ 前端组件 |
| xlsx 读写库 | exceljs / xlsx 库 | NPOI / EPPlus | EPPlus / NPOI |
| 跨平台扩展 | ✅ 可扩展 macOS/Linux | ✅ Avalonia 可跨平台 | ❌ 仅 Windows |
| 开发者技能要求 | TypeScript + Vue3 | C# + XAML | C# + HTML/JS |
| 适合人群 | 前端背景开发者 | .NET 原生开发者 | .NET + 前端混合背景 |

### 2.2 推荐路线

#### 场景一：追求开发效率与 UI 体验 → 路线 A（Electron + Vue3）

**推荐理由**：
- 六大视图的核心交互组件（看板拖拽、甘特图、日历、流式卡片）在前端生态中都有成熟开源实现
- 不需要从零造 UI 轮子，开发周期最短
- UI 体验最接近飞书多维表

**技术栈**：
```
前端：Vue 3 + TypeScript + Vite
UI 组件：
  - 表格：vxe-table / AG Grid（虚拟滚动）
  - 看板：vue-kanban / @hello-pangea/dnd（拖拽）
  - 画册：CSS Grid / Flexbox（原生流式布局）
  - 日历：FullCalendar
  - 甘特：vue-gantt-task / frappe-gantt
文件解析：exceljs（读写 xlsx）/ papaparse（csv）
状态管理：Pinia
打包：electron-builder → 单文件 exe
```

**风险点**：
- exe 体积偏大（80-150MB），含 Chromium 内核
- 大文件（>5万行）需实现虚拟列表
- Node.js 与前端通信需要 IPC 桥接

#### 场景二：追求原生性能与小体积，且有 .NET 背景 → 路线 C（.NET WinForms/WPF + WebView2）

**推荐理由**（特别适合你的背景）：
- 你有 VB.NET/COM 和 VSTO 开发经验，C# 上手无障碍
- WebView2 嵌入方案可复用前端 Vue 组件，避免纯 WPF 自研全部视图
- exe 体积和内存占用介于 Electron 与纯 WPF 之间
- 文件 IO 用 EPPlus/NPOI，成熟稳定

**技术栈**：
```
后端：.NET 8 (C#) + WinForms 或 WPF
内嵌浏览器：WebView2（Edge Chromium 内核）
前端：Vue 3 + TypeScript（同路线 A 前端部分）
文件解析：EPPlus（读写 xlsx）/ CsvHelper（csv）
通信：WebView2 的 PostMessage / WebMessageReceived 桥接
打包：MSIX 或 Inno Setup
```

**架构**：
```
┌─────────────────────────────────────┐
│         桌面主窗口 (WinForms/WPF)      │
│  ┌───────────────────────────────┐   │
│  │      WebView2 控件             │   │
│  │  ┌─────────────────────────┐ │   │
│  │  │   Vue3 前端应用           │ │   │
│  │  │  (6大视图 + 交互组件)      │ │   │
│  │  └─────────────────────────┘ │   │
│  └───────────────────────────────┘   │
│           ↕ 消息桥接                  │
│  ┌───────────────────────────────┐   │
│  │   C# 后端服务层                │   │
│  │  - 文件解析 (EPPlus/NPOI)      │   │
│  │  - 视图引擎 ViewEngine         │   │
│  │  - 数据同步管理器              │   │
│  │  - 视图配置 JSON 读写          │   │
│  └───────────────────────────────┘   │
└─────────────────────────────────────┘
```

#### 场景三：极致轻量，无浏览器内核 → 路线 B（纯 .NET WPF/Avalonia）

**不推荐作为首选**，除非对 exe 体积和内存有严格要求。所有视图 UI（看板拖拽、甘特时间轴、画册流式布局、日历网格）均需自研，开发量巨大。

### 2.3 最终建议

| 你的情况 | 推荐路线 |
|---------|---------|
| 有前端开发经验，追求快速出产品 | 路线 A：Electron + Vue3 |
| 有 .NET/C# 背景，希望兼顾性能和开发效率 | **路线 C：.NET + WebView2**（首选推荐） |
| 极度在意体积，接受大量 UI 自研 | 路线 B：纯 WPF/Avalonia |

> **结合你的 VB.NET/COM/VSTO 技术背景，推荐路线 C（.NET 8 + WebView2 + Vue3 前端）**。C# 后端处理文件 IO 和业务逻辑，前端 Vue3 负责视图渲染和交互，两者通过 WebView2 消息桥接通信。这样既利用了你的 .NET 技能，又复用了前端成熟的视图组件生态。

## 三、系统架构设计

### 3.1 整体架构

```
独立桌面应用
├── 文件解析层 (FileAdapter)
│   ├── XlsxAdapter：EPPlus/NPOI 读写 xlsx
│   ├── CsvAdapter：CsvHelper 读写 csv
│   └── ConfigAdapter：视图配置 JSON 读写
│
├── 核心业务层 (Core)
│   ├── DataModel：内存数据模型
│   │   ├── DataTable：行记录集合 List<DataRow>
│   │   ├── DataRow：Dictionary<string, object> 键值对
│   │   └── FieldSchema：字段名、类型推断
│   │
│   ├── ViewConfigManager：视图配置管理器
│   │   ├── 加载/保存 .multiview.json
│   │   ├── 视图 CRUD（新建/编辑/删除视图）
│   │   └── 当前活动视图切换
│   │
│   ├── ViewEngine：视图引擎（核心）
│   │   ├── 输入：原始全量数据集 + 单个视图配置
│   │   ├── Filter：条件过滤
│   │   ├── Sort：多字段排序
│   │   ├── Group：按字段分组
│   │   └── 输出：过滤+排序+分组后的视图数据集
│   │
│   └── DataSyncManager：数据同步管理器
│       ├── UI 编辑 → 内存数据集 → 磁盘文件
│       ├── 批量保存 / 手动保存
│       └── 脏数据标记 + 防抖自动保存
│
├── UI 桥接层 (Bridge)
│   ├── MessageBridge：C# ↔ JS 双向通信
│   │   ├── GetData：推送数据到前端
│   │   ├── UpdateCell：前端编辑回写
│   │   ├── SaveFile：触发保存
│   │   └── LoadView：切换视图
│   └── ViewStateSync：视图状态同步
│
├── UI 渲染层 (Vue3 Frontend)
│   ├── 表格视图 Table（虚拟滚动）
│   ├── 表单视图 Form（动态控件）
│   ├── 看板视图 Kanban（拖拽分组）
│   ├── 画册视图 Gallery（流式卡片）
│   ├── 日历视图 Calendar（FullCalendar）
│   └── 甘特视图 Gantt（进度条拖拽）
│
└── 持久化模块
    ├── 业务数据：xlsx/csv（用户原始文件）
    └── 视图配置：{文件名}.multiview.json（同目录）
```

### 3.2 数据流设计

```
┌──────────┐     读取      ┌──────────────┐
│ xlsx/csv │ ──────────→  │  内存数据集   │
│ (磁盘)   │              │ (权威数据源)  │
└──────────┘              └──────┬───────┘
     ↑                           │
     │ 保存写回                    │ 传入 ViewEngine
     │                           ↓
┌──────────┐              ┌──────────────┐
│multiview │   加载/保存   │  ViewEngine   │
│ .json    │ ←──────────→ │ 过滤/排序/分组 │
│(视图配置) │              └──────┬───────┘
└──────────┘                     │
                                 ↓ 视图数据集
                          ┌──────────────┐
                          │  UI 渲染层    │
                          │ (6大视图组件) │
                          └──────┬───────┘
                                 │
                                 ↓ 用户编辑
                          ┌──────────────┐
                          │ DataSyncMgr  │
                          │ 回写内存→磁盘  │
                          └──────────────┘
```

**关键原则**：
- 内存数据集是唯一权威数据源，UI 所有视图共享同一份数据
- 视图配置不修改原始数据，只做展示变换
- 编辑操作必须落地到内存数据集，再持久化到磁盘

- `views`：视图配置数组，每个视图独立配置筛选、分组、排序、可见字段、卡片布局

### 3.4 内存数据模型

```
// C# 伪代码
public class DataRow
{
    public int RowIndex { get; set; }          // 行索引（临时主键）
    public Dictionary<string, object> Values { get; set; }  // 列名 → 值
}

public class DataTable
{
    public string SourceFile { get; set; }
    public string SheetName { get; set; }
    public List<FieldSchema> Fields { get; set; }
    public List<DataRow> Rows { get; set; }
    public bool IsDirty { get; set; }         // 脏数据标记
}

public class FieldSchema
{
    public string Name { get; set; }
    public FieldType Type { get; set; }       // Text/Number/Date/Select/Image
    public List<string> Options { get; set; } // Select 类型的选项列表
}
```

## 四、核心模块详细设计

### 4.1 文件解析层

#### xlsx 读写
- 使用 EPPlus（.NET）或 exceljs（Node）读写 xlsx，**不调用 Excel COM**
- 读取：将工作表转为 `List<DataRow>` 内存模型，每行是 `Dictionary<string, object>`
- 保存：内存数据集完整写回 xlsx，**不增量改写单元格**，避免格式错乱
- 注意：普通 Excel 无主键，内部使用行索引作为临时主键

#### csv 读写
- 处理编码（GBK/UTF-8 自动检测）
- 分隔符自动识别（逗号/分号/制表符）

#### 视图配置 JSON
- 使用 `System.Text.Json`（.NET）或原生 `JSON.parse`（Node）
- 配置文件与 xlsx 同目录，命名 `{文件名}.multiview.json`
- 文件复制/重命名时需同步处理配置文件

#### 风险提示
> Excel 原有的部分格式（条件格式、宏、图表、合并单元格）经第三方库读写后会丢失。本软件定位是数据查看编辑工具，不完整保留 Excel 复杂样式。

### 4.2 视图引擎 ViewEngine（核心模块）

ViewEngine 是与 UI 无关的纯逻辑模块，负责将原始数据 + 视图配置变换为视图数据集。

```
输入：
  - 原始全量数据集（List<DataRow>）
  - 单个视图配置（ViewConfig）

处理流程：
  1. Filter：根据 filter 表达式过滤行
  2. Sort：根据 sort 配置多字段排序
  3. Group：根据 groupBy 字段分组（看板视图）

输出：
  - 视图数据集（过滤+排序+分组后的行集合）

重要：全部在内存完成，不修改磁盘 xlsx 源文件
```

#### 筛选表达式设计
支持简单表达式语法：
- `[状态] = '进行中'` — 等于
- `[截止日期] >= '2026-01-01'` — 日期比较
- `[负责人] != ''` — 非空
- `[状态] IN ('进行中', '已完成')` — 多值匹配
- `[状态] = '进行中' AND [优先级] = '高'` — 组合条件

### 4.3 双向数据同步机制

```
用户在 UI 编辑（看板拖拽/表单输入/甘特拖拽）
        ↓
  DataSyncManager 接收编辑指令
        ↓
  修改内存数据集对应行 → 标记 IsDirty = true
        ↓
  ┌─ 手动保存（Ctrl+S / 保存按钮）
  │   → 内存数据集完整序列化写回 xlsx
  │
  └─ 自动保存（防抖 3 秒）
      → 检测 IsDirty → 异步写回磁盘
```

**注意事项**：
- 不要只改 UI 副本，内存必须维护唯一权威数据集
- 切换视图时，全部基于同一份内存数据集重新执行 ViewEngine 渲染
- 保存时**完整写回** xlsx，不做增量单元格更新

### 4.4 六大视图实现要点

#### 表格视图 Table
- 使用虚拟滚动表格组件（vxe-table / AG Grid）
- 支持列隐藏、列排序、列宽调整
- 支持行内编辑（双击单元格编辑）

#### 表单视图 Form
- 根据字段类型动态生成输入控件：
  - text → 文本框
  - number → 数字输入
  - date → 日期选择器
  - select → 下拉框
  - image → 文件路径选择 + 图片预览
- 单条记录弹窗编辑模式

#### 看板视图 Kanban
- 按 GroupBy 字段分组生成多列
- 每列内卡片纵向排列
- 卡片跨列拖拽 → 修改对应记录的分组字段值 → 回写内存数据集
- 拖拽组件：@hello-pangea/dnd（React）/ vue-draggable（Vue）

#### 画册视图 Gallery
- 流式卡片网格布局（CSS Grid / Flexbox Wrap）
- 图片优先展示（存储本地文件路径，软件根据路径加载图片）
- 次要字段作为卡片简介文字
- **必须实现虚拟化**，否则上千张卡片渲染卡死

#### 日历视图 Calendar
- 绑定一个日期字段
- 把记录渲染到日历对应日期格子
- 使用 FullCalendar 组件（成熟开源）
- 支持月/周/日视图切换

#### 甘特视图 Gantt
- 绑定开始日期、结束日期字段
- 绘制横向进度条
- 拖拽进度条修改起止时间 → 回写数据
- 使用 vue-gantt-task / frappe-gantt 组件

### 4.5 性能关键点

| 场景 | 措施 |
|------|------|
| 行数 > 1万行 | 必须开启虚拟列表/虚拟卡片，只渲染可视区域 |
| 画册大量图片 | 图片懒加载 + 虚拟滚动 |
| xlsx 读写 | 不频繁保存；手动保存按钮 + 防抖自动保存 |
| 内存数据集 | 全量加载到内存，避免频繁磁盘 IO |
| 视图切换 | ViewEngine 计算结果缓存，相同配置不重复计算 |
| 图片字段 | 不嵌入 xlsx，只保存本地绝对/相对路径 |

## 五、开发阶段规划

### 阶段 1：基础底座（MVP 核心通路）

**目标**：打通文件读取 → 内存模型 → 视图引擎 → 表格视图 → 保存回写的完整链路

| 任务 | 说明 |
|------|------|

## 六、风险评估与对策

| 风险 | 等级 | 影响 | 对策 |
|------|------|------|------|
| xlsx 复杂样式丢失 | 中 | 用户原 Excel 有宏/图表/条件格式，读写后丢失 | 定位为数据工具，明确告知不支持复杂样式保留 |
| 大文件性能瓶颈 | 中 | >5万行时加载和渲染卡顿 | 虚拟列表 + 分页加载 + 异步解析 |
| 视图配置文件丢失 | 低 | 复制 xlsx 时忘记连带复制 .json | 软件检测缺失配置时提示用户；可选嵌入 OpenXML 自定义部件 |
| WebView2 运行时缺失 | 中 | 目标机器无 Edge/WebView2 | 打包时捆绑 WebView2 固定版本引导安装 |
| 图片路径失效 | 低 | 用户移动图片文件后路径失效 | 支持相对路径 + 图片不存在时显示占位图 |
| 字段类型推断错误 | 低 | 日期被识别为文本、数字被识别为文本 | 提供手动修正字段类型功能 |
