# 画册视图 — 结构、图片来源与分组拖拽机制说明

> 适用版本：v2.9.42（2026-08-20）
> 源码位置：`MultiTableAddin/src/MultiTableAddin/Html/index.html`
> 适用对象：想了解画册内部结构与二次开发的人员

画册视图在「分组」状态下**复用同一套 DOM 结构与高度链**（分组分支直接复用看板式 `.kanban-cols` / `.kanban-col` 列布局，并复用 `enableKanbanDrag` 分组拖拽机制）。画册比其它视图多了「图片」维度（两种图片来源 + 两种显示形状）与「分组拖拽改分组字段」交互。下文先讲画册结构，再讲共用的高度/滚动机制与分组拖拽。

---

## 一、画册视图结构

### 1.1 数据模型：`cardMeta`

画册视图的配置存在当前视图对象的 `cardMeta` 字段中（由「视图设置」面板写入并 `saveConfig` 持久化）：

| 字段 | 类型 | 说明 |
|------|------|------|
| `cardMeta.image` | string | **图片字段名**（字段类型为 `Image`）。来源①：字段值即图片地址 |
| `cardMeta.title` | string | 卡片标题字段名 |
| `cardMeta.colorField` | string | 分色字段名（`Select`/`Quarter`/`Text`），给卡片顶部加彩色边 |
| `cardMeta.imageFolder` | string | **图片文件夹路径**。来源②：开启「文件夹模式」时按文件名匹配 |
| `cardMeta.imageMatchField` | string | **图片匹配字段名**。文件夹模式下，按该字段的值去匹配文件夹内图片文件名 |
| `cardMeta.imageShape` | `'normal'` / `'circle'` | 图片显示形状：正常矩形 / 圆形居中裁剪 |

> 视图级开关 `cfg.showFieldLabels`（默认显示）控制卡片字段是否显示「字段名：值」的标签。

### 1.2 渲染流程

```
renderGallery()
  ├─ 无 cardMeta → 占位提示「请先在视图设置中设置图片与标题字段」
  ├─ 若 folderMode（已设 imageFolder 且已设 imageMatchField）
  │     → ensureGalleryImageMap(folder) 拉取文件夹图片清单（异步）
  │     → 回调里 renderGalleryInner(cfg)
  └─ 否则直接 renderGalleryInner(cfg)

renderGalleryInner(cfg)
  ├─ groupBy = viewGroupField(v)      // 默认 '' = 不分组
  ├─ buildCard(r)                     // 单卡构建，分组/不分组共用
  ├─ buildGrid(rows)                  // .gallery-grid 容器
  ├─ 若 !groupBy（不分组）：content ← buildGrid(getVisibleRows())   // 单列网格
  └─ 若 groupBy（分组）：复用看板布局
        host=.kanban-cols
          └─ 每组 → grp=.kanban-col.gallery-group-col
                ├─ .kanban-col-head（组名 + 计数）
                └─ .kanban-col-body → buildCard(r) 列表
        wrap=.kanban-wrap → 包 host → content
```

**关键方法（index.html）**
- `renderGallery()` ≈ 行 2043
- `renderGalleryInner(cfg)` ≈ 行 2052
- `buildCard(r)` ≈ 行 2063（抽出的单卡构建，分组/不分组共用）
- `buildGrid(rows)` ≈ 行 2091
- `viewGroupField(v)` — 取当前视图的分组字段名（工具栏「分组」下拉写入）

### 1.3 图片的两种显示方式（图片来源）

画册的图片**有两条互不相同的来源**，且**文件夹模式优先于图片字段**。

#### 来源①：图片字段模式
- 条件：配置了 `cardMeta.image`（图片类型字段），且**未**开启文件夹模式。
- 取值：`imgPath = String(r.values[imgField] || '').trim()`。
- 字段值即图片地址，支持三种形式：
  - 本地路径（如 `D:/images/P001.jpg`）
  - `http(s)://` 远程地址
  - `data:` 内嵌 base64
- 在 `buildCard` 中：`else { imgPath = imgField ? r.values[imgField] : '' }`。

#### 来源②：文件夹匹配模式（folder mode）
- 条件：**同时**配置了 `cardMeta.imageFolder`（文件夹路径）**和** `cardMeta.imageMatchField`（匹配字段）才算开启。
  - 注意：只配其中一个不会生效，会自动退回来源①。
- 取值：`imgPath = resolveImagePath(_galleryImgMap, r.values[matchField])`。
- 匹配规则（`resolveImagePath` + `imgFileKey`）：
  1. 把文件夹内每个文件名做「去扩展名 + trim + 转小写」得到 key，建立 `key → 完整路径` 映射；
  2. 先用记录字段值（同样去扩展名小写）做**精确匹配**；
  3. 未命中则做**前缀匹配**：`key.indexOf(字段值去扩展名小写 + '_') === 0` 即命中（例如文件 `P001_2.jpg` 可匹配字段值 `P001`）。
- 文件夹清单由 `ensureGalleryImageMap(folder, cb)` 经 `api.call('listImageFiles', {folder})` 向 C# 拉取，并缓存到 `_galleryImgMap` / `_galleryImgFolder`（同文件夹不重复拉取）。

> 两条来源最终拿到的 `imgPath` 若是本地路径，都会走同一个 `setImgSrc` → C# `getImageBase64` 转 base64 显示（见 1.5）。

### 1.4 图片显示形状（imageShape）

- `normal`（默认）：图片充满卡片图区（`.gimg` 高度 120px，`object-fit:cover`）。
- `circle`（圆形居中裁剪）：图区渲染为 `.gimg.circle`（104×104、`border-radius:50%`、水平居中），图片按圆形裁切。
- 仅改变**显示裁切**，不修改原图文件。
- 设置入口：视图设置 → 图片显示模式 → 正常（矩形）/ 圆形（居中裁剪），写入 `cardMeta.imageShape`。

### 1.5 本地图片加载（WebView2 限制）

`setImgSrc(img, rawPath, cb)` 处理图片地址：
- 空 → `alt=''`；
- `data:` / `http(s):` / `blob:` → 直接使用；
- 本地路径 → 剥掉 `file://` 前缀 → `api.call('getImageBase64', {path})` 由 C# 读文件返回 base64 data URI，写入 `img.src`；
- 结果按路径缓存到 `_imgDataUriCache`，避免重复请求；
- 加载失败 → `alt='图片加载失败'`。

> **铁律**：WebView2 用 `NavigateToString` 加载的页面 origin 为 `null/about:blank`，`<img src="file://...">` 会被浏览器拦截。本地图片**必须**经 C# 转 base64，不能在 HTML 里直接写 `file://`。

### 1.6 分组 vs 不分组

| 模式 | 触发 | DOM 结构 | 滚动行为 |
|------|------|----------|----------|
| 不分组 | `groupBy === ''` | `.gallery-grid` 单列网格 | 卡片在 `.content` 内整体纵向滚动 |
| 分组 | 工具栏「分组」选了字段 | `.kanban-wrap > .kanban-cols > .kanban-col.gallery-group-col`（看板式列布局） | 每列等高，列内 `.kanban-col-body` 独立纵向滚动（见第二节） |

- 分组聚合：`displayText(groupBy, r)` 作为组 key，`（空）` 表示空值；`Select`/`Quarter` 分组按选项顺序，`（空）` 追加在末尾。
- 分组时每组标题显示「组名 + 记录数」。
- 空字段在卡片里渲染为浅色占位「—」（`v-empty`），**保证卡片高度按字段数统一**（不会因为某条没填就变矮）。

### 1.7 画册关键参数 / 方法一览

| 名称 | 位置 | 作用 |
|------|------|------|
| `cardMeta.image` | 视图配置 | 图片字段（来源①） |
| `cardMeta.imageFolder` / `imageMatchField` | 视图配置 | 文件夹模式（来源②），须同时设置 |
| `cardMeta.imageShape` | 视图配置 | `normal` / `circle` |
| `cardMeta.colorField` | 视图配置 | 卡片顶部彩色边 |
| `cardMeta.title` | 视图配置 | 卡片标题字段 |
| `viewGroupField(v)` | index.html | 取分组字段名 |
| `ensureGalleryImageMap(folder, cb)` | index.html | 拉取文件夹图片清单并缓存 |
| `resolveImagePath(map, value)` | index.html | 按值匹配文件夹图片路径 |
| `imgFileKey(name)` | index.html | 去扩展名+小写，用于匹配 |
| `setImgSrc(img, rawPath, cb)` | index.html | 统一图片加载（含 C# base64） |
| `_galleryImgMap` / `_galleryImgFolder` | index.html | 文件夹图片缓存 |

### 1.8 画册注意事项

1. **文件夹模式必须同时设 `imageFolder` 与 `imageMatchField`**，否则退回图片字段模式。
2. **匹配按文件名、忽略扩展名与大小写**，并支持 `值_序号` 前缀（如 `P001_2.jpg` ↔ 值 `P001`）。
3. **本地图片地址写在字段里应是真实路径**，不要带 `file://`（由 `setImgSrc` 统一处理）；远程图用 `http(s)://`。
4. **圆形只是显示裁切**，原图不变。
5. **分组复用看板式列布局**，所以卡片高度规则与分组列一致（见第二节 `flex:0 0 auto`）。
6. 改 `index.html` 里任何 CSS 类名 / 数值 / 文案后，必须同步更新 `verify-build.py` 的对应检查串，并 `build → copy DLL` 才真正生效。

## 二、高度、滚动与分组色条（画册分组）

分组后的画册**完全复用同一套 flex 高度链**。目标是：**每列等高（= 内容区高度），列内卡片纵向排列，记录多时列内独立出垂直滚动条，且卡片不被压扁**。

### 2.1 高度链（从外到内）

```
.content{ flex:1; min-height:0; overflow:hidden }            /* 内容区：min-height:0 是内部能滚动的前提 */
  └─ .kanban-wrap{ height:100% }                            /* 包裹层：撑满内容区 */
       └─ .kanban-cols{ height:100%; overflow:auto }        /* 列容器：列多时出水平滚动条 */
            └─ .kanban-col{ flex:0 0 240px; min-height:0; overflow:hidden }  /* 每列固定宽；min-height:0 关键 */
                 └─ .kanban-col-head{ ... }                 /* 组名 + 计数 */
                 └─ .kanban-col-body{ flex:1; overflow:auto } /* 列内：垂直滚动条在这里 */
                      └─ .kanban-card / .gallery-card{ flex:0 0 auto } /* 卡片不被压缩 */
```

### 2.2 关键 CSS 规则

- `.content` 必须 `min-height:0`，否则内部 `overflow:auto` 失效、整页被撑高。
- `.kanban-col` 必须 `min-height:0`，否则 `.kanban-col-body` 拿不到确定高度，滚动不出。
- **`.kanban-col-body > .kanban-card, .kanban-col-body > .gallery-card { flex:0 0 auto }`** 是修复「卡片高度不齐」的核心：卡片保持自然高度，溢出时由 `.kanban-col-body` 出滚动条。若漏掉这条，flex 容器会按「溢出量 ÷ 列高」**等比压扁**每张卡片，且各组卡片数不同 → 压缩比不同 → 视觉上每组高度都不一样（v2.9.37 #465 的根因）。

### 2.3 常见坑

| 现象 | 原因 | 修复 |
|------|------|------|
| 分组列高度随记录数伸缩 | 缺 `.kanban-wrap{height:100%}` 包裹层 | 分组分支对齐：host 先包进 `.kanban-wrap` 再进 content |
| 卡片被压扁、高度不一 | `.kanban-col-body` 是 `flex column`，子项默认 `flex-shrink:1` | 子项显式 `flex:0 0 auto` |
| 列内不出滚动条、内容被裁 | `.kanban-col` 没 `min-height:0` | 给 `.kanban-col` 加 `min-height:0` |
| 整页滚动而不是列内滚动 | `.content` 没 `min-height:0` | 给 `.content` 加 `min-height:0; overflow:hidden` |

### 2.4 分组列顶部分组色条（画册分组）

分组后每列（`.kanban-col`）的列头（`.kanban-col-head`）顶部有一条**分组色条**：高 3px、与列头等宽的一条实心彩色横条，颜色与分组一一对应。画册分组**复用同一套色条机制**。除色条外，整列边框与整列背景也会用同色（边框同色、背景为同色约 6% 浅底）。

#### 颜色从哪来（固定调色板 + 序号）

颜色**不是用户设置的**，而是按「分组在列表中的序号」从**固定调色板**循环取色：

```js
// index.html ≈ 行 2102（画册分组）
var groupColors=['#3370FF','#14C9C9','#FF7D00','#F76965','#9FDB60','#CA62E8','#FFC53D','#6E4AE0'];
...
var color=groupColors[idx % groupColors.length];   // idx = 该分组在 keys 中的下标
```

调色板共 8 色，超过 8 个分组会 `idx % 8` 循环复用。第 1 个分组恒为 `#3370FF`，第 2 个 `#14C9C9`，依此类推。

#### 颜色如何落到 DOM（CSS 变量）

每列建好后写入内联样式，核心是设置一个 CSS 自定义属性 `--group-color`：

```js
// ≈ 行 2106-2108（画册分组）
col.style.setProperty('--group-color', color);   // 色条 / 边框 / 底色的统一来源
col.style.backgroundColor = color + '10';          // 整列浅底（hex + '10' = 约 6% 不透明度）
col.style.borderColor = color;                    // 整列边框同色
```

- `--group-color` 是整条色条 / 边框 / 底色的**单一来源**，下文 CSS 全部引用它；
- 内联 `backgroundColor` / `borderColor` 优先级高于样式表，会覆盖 `.kanban-col[style*="--group-color"]` 里的渐变 / 边框，最终显示「同色 6% 浅底 + 同色 1px 边框」。

#### 色条本体（CSS）

```css
/* ≈ 行 143 */
.kanban-col-head{ border-top:none; box-shadow:inset 0 3px 0 0 var(--group-color, var(--border)); }
```

- 色条用 **`box-shadow: inset 0 3px 0 0`** 实现：`inset` 表示画在元素**内部**的阴影；`0 3px 0 0` = 水平偏移 0、垂直偏移 3px（向下 3px）、模糊 0、扩散 0 → 紧贴 header 顶边、**高 3px、与 header 等宽**的一条实心横条。
- 颜色取 `var(--group-color, var(--border))`：有分组色用分组色，无分组色退回 `--border`（灰边），因此未分组 / 未着色时也不会报错。
- 列容器还有一条浅底 + 同色边框规则（约行 144，实际被上面的内联样式覆盖为背景浅底 + 同色边框）：

  ```css
  .kanban-col[style*="--group-color"]{ background:linear-gradient(to bottom,var(--group-color-bg,#f7f8fa) 0,#f7f8fa 100%); border:1px solid var(--group-color,var(--border)); }
  ```

#### 关键参数 / 方法

| 名称 | 位置 | 作用 |
|------|------|------|
| `groupColors` 数组 | 行 2102 | 固定调色板（8 色），按分组序号取色 |
| `idx % groupColors.length` | 行 2106 | 分组序号 → 颜色 |
| `--group-color` CSS 变量 | 行 2108（`setProperty`）| 色条 / 边框 / 底色的统一来源 |
| `box-shadow: inset 0 3px 0 0 var(--group-color,…)` | 行 143（`.kanban-col-head`）| 顶部分组色条本体；`3px` 即色条高度 |
| `color + '10'` / `borderColor = color` | 行 2106 起 | 整列浅底 + 同色边框 |

#### 注意事项

1. **颜色目前非用户可配**：当前颜色由固定 8 色调色板按分组序号自动分配，没有「分组色」设置项（与其它视图的「分色字段」是两回事——分色字段是给卡片 / 条形加彩，不是这条列头色条）。要换配色直接改 `groupColors` 数组。
2. **色条高度 3px 写死在 CSS**：`box-shadow` 的 `3px` 是硬编码，无设置项；要加粗 / 变细改行 143 的 `3px`。
3. **换色逻辑只改一处**：任何想改色条颜色来源（如改为「按字段值取色」「用户自定义色」）都应改 `setProperty('--group-color', …)` 的取值，CSS 无需动。
4. 改动后同样要同步 `verify-build.py` 检查串并重新构建。

## 三、画册分组拖拽（看板式列布局）

### 3.1 结构（画册分组模式）

- 分组字段 `groupBy = cfg.groupBy`（由工具栏「分组」下拉选择并写入视图配置）；分组后每组渲染为一列（`.kanban-col.gallery-group-col`），列头显示组名 + 计数；未分组时画册走单列网格（见 1.6）。
- `titleField`：优先 `cardMeta.title`，未设则取第一个 `Text` 字段。
- 分组聚合：同画册——`displayText(groupBy, r)` 为 key，`（空）` 表示空值；`Select`/`Quarter` 按选项顺序。
- 每列：`col.dataset.group = k`（组名，用于拖拽落点判定）；列头显示组名 + 计数。
- 每张卡：`.gallery-card`，含标题 + `.gfld`（可见字段，排除标题；空值显示「—」/ `v-empty`）。
  - 点击 → `selectRow`（不弹详情面板）；右键 → `showRecordContextMenu`。
  - 末尾调用 **`enableKanbanDrag(card, r, groupBy)`** 绑定拖拽（画册分组模式复用同一套拖拽机制）。

### 3.2 拖拽更新全流程（enableKanbanDrag）

> **重要：分组拖拽不用 HTML5 原生 DnD**（WebView2 中 HTML5 拖放不稳定），而是用**鼠标事件**模拟。

1. **mousedown（仅左键）**：`preventDefault`；清空选区；`document.body` 加 `kanban-dragging`；记录 `startX/startY`、`moved=false`、卡片 `rect`；暂存 `state._kanbanDragCard/_kanbanDragRow/_kanbanDragGroupBy`。
2. **mousemove**：位移超 3px 视为拖动 → 克隆一张 `ghost`（`position:fixed`、跟随光标）并给原卡加 `dragging` 类。
3. **mouseup**：
   - 移除监听、移除 ghost、去掉 `dragging` / `kanban-dragging`；
   - 若 `moved`：用 `document.elementsFromPoint(clientX, clientY)` 找到光标下最近的 `.kanban-col` 作为 `targetCol`（即使光标落在某张卡片上，也会向上冒泡到所在列）；
   - `newVal = targetCol.dataset.group === '（空）' ? '' : targetCol.dataset.group`（拖到「空」组 = 清空该字段）；
   - `oldVal = r.values[groupBy]`；若 `newVal !== oldVal`：
     - 更新内存 `state.rows[rowIndex].values[groupBy] = newVal`（并删 `displayTexts[groupBy]`）；
     - `selectRow(rowIndex)` → `renderContent()`（即时重排）；
     - **持久化**：`api.call('updateCell', { rowIndex, field: groupBy, value: newVal })`
       - 成功 → `renderContent()` + `toast('已移动到「X」')`；
       - 失败 → `toast('移动失败…')` + `openTable(...)` 重新拉取，防止前后端不一致。

### 3.3 画册分组拖拽关键参数 / 方法

| 名称 | 位置 | 作用 |
|------|------|------|
| `cfg.groupBy` | 视图配置 | 分组字段名（工具栏「分组」下拉写入） |
| `cardMeta.title` | 视图配置 | 卡片标题字段 |
| `enableKanbanDrag(card, r, groupBy)` | index.html（画册分组模式复用） | 绑定拖拽 |
| `state._kanbanDragCard/_kanbanDragRow/_kanbanDragGroupBy` | index.html | 拖拽会话临时状态 |
| `targetCol.dataset.group` | DOM | 落点列对应的分组值 |
| `api.call('updateCell', {rowIndex, field, value})` | JS → C# | 把新分组值写回工作表 |

### 3.4 画册分组拖拽注意事项

1. **拖拽只改分组字段**：落点列对应的 `groupBy` 字段值被改写并 `updateCell` 持久化，其它字段不变。
2. **落点判定用 `elementsFromPoint` + `closest('.kanban-col')`**：即使悬停在卡片上也能正确找到所属列；拖到「（空）」组会把字段清空。
3. **先本地重排再异步落盘**：`renderContent()` 立即重排，随后 `updateCell` 写回；若写回失败会重新打开表以同步，避免「界面动了但数据没存」。
4. **非原生 DnD**：用 `mousedown/mousemove/mouseup` 模拟，因此不要试图用 HTML5 `draggable` 属性。
5. **列高/滚动与画册分组一致**：见第二节高度链（`flex:0 0 auto` 防压扁）。
6. 改动拖拽逻辑后同样要同步 `verify-build.py` 检查串并重新构建。

## 五、常见错误排查

| 现象 | 可能原因 | 解决 |
|------|---------|------|
| 画册不显示图片 | 用的是本地路径但写了 `file://`，或被浏览器拦截 | 字段只写真实路径，由插件经 C# 转 base64；远程图用 `http(s)://` |
| 文件夹模式不生效 | 只设了 `imageFolder` 或只设了 `imageMatchField` | 两个必须同时设置 |
| 文件夹图片匹配不到 | 文件名与字段值去扩展名后不匹配 | 用 `值` 或 `值_序号` 命名文件；确认匹配字段取值正确 |
| 分组列高度参差 / 卡片被压扁 | 缺 `flex:0 0 auto` 或 `.kanban-wrap` 包裹层 | 按第二节高度链补齐 CSS |
| 列内不出滚动条、内容被裁 | `.kanban-col` / `.content` 缺 `min-height:0` | 补 `min-height:0` |
| 画册分组拖拽无反应 | 未开启「分组」（画册分组拖拽仅在分组模式下生效） | 先在工具栏「分组」下拉选分组字段 |
| 拖拽后数据没保存 | `updateCell` 写回失败（如工作表被占用） | 看 toast 提示，插件会自动重新打开表同步 |
| 分组色条不显示 / 颜色不对 | `--group-color` 未写入或被覆盖 | 检查 `setProperty('--group-color', …)`（行 1935 / 2108）是否执行；色条依赖该变量 |
