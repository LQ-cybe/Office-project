# 多维表窗口状态实现说明（跟随 Excel 最小化 / 阻塞问题 / 强制置顶）

> 适用版本：v2.9.3（代号 WindowUX，2026-08-12）
> 涉及文件：
> - `src/MultiTableAddin/Html/HtmlMainForm.cs`（主窗口）
> - `src/MultiTableAddin/RibbonController.cs`（功能区按钮入口）
> - `src/MultiTableAddin/Html/index.html`（设置面板 / 置顶与最大化开关）

---

## 1. 需求背景

用户希望多维表主窗口满足三条看似矛盾的体验：

1. **跟随 Excel 最小化一起隐藏**：把 Excel 主窗口最小化时，多维表窗口也自动隐藏；还原 Excel 时再自动显示。这样它像是 Excel 的“附属面板”，而不是一个独立的桌面程序。
2. **不阻塞 Excel 任务栏**：之前窗口以 Excel 为“拥有窗口”弹出，导致在任务栏单击 Excel 无法最小化/切换（被多维表窗口阻塞）。需要去掉这种阻塞。
3. **可强制置顶**：用户可在设置中勾选“窗口置顶”，让窗口始终在最前；也能勾选“打开时最大化”。

关键难点在于：**第 1 点与第 2 点通常是冲突的**——用“拥有窗口（owned window）”能天然实现“随父窗口最小化而隐藏”，但正是它造成了任务栏阻塞。下面说明本版如何用“非拥有窗口 + WinEvent 钩子”同时达成三点。

---

## 2. “跟随 Excel 最小化一起隐藏”的实现方法

### 2.1 核心思路

不再把多维表窗口设为 Excel 的拥有窗口，而是：

- 用 `form.Show()`（**不带 owner**）以无模式（modeless）方式显示；
- 设置 `ShowInTaskbar = false`，让它不单独占据一个任务栏按钮；
- 通过 **WinEvent 钩子**（`SetWinEventHook`）监听 Excel 主窗口的最小化/还原系统事件，手动同步本窗口的 `Visible`。

这样既去掉了“拥有窗口”带来的阻塞，又用钩子“模拟”出了“随 Excel 一起隐藏”的效果。

### 2.2 关键代码（HtmlMainForm.cs）

```csharp
// 监听 Excel 主窗口的最小化/还原
private void AttachExcelMinimizeFollow()
{
    _excelHwnd = ExcelDnaUtil.WindowHandle;      // Excel 主窗口 HWND
    if (_excelHwnd == IntPtr.Zero) return;
    uint pid;
    GetWindowThreadProcessId(_excelHwnd, out pid);
    _winEventDelegate = OnWinEvent;
    _winEventHook = SetWinEventHook(
        EVENT_SYSTEM_MINIMIZESTART, EVENT_SYSTEM_MINIMIZEEND,
        IntPtr.Zero, _winEventDelegate, pid, 0,
        WINEVENT_OUTOFCONTEXT | WINEVENT_SKIPOWNPROCESS);
}

private void OnWinEvent(...)
{
    if (hwnd != _excelHwnd || idObject != 0) return;   // 只关心 Excel 主窗口本身
    if (eventType == EVENT_SYSTEM_MINIMIZESTART)
        PostToUi(() => { if (!IsDisposed && Visible) Visible = false; });   // Excel 最小化 → 隐藏
    else if (eventType == EVENT_SYSTEM_MINIMIZEEND)
        PostToUi(() => { if (!IsDisposed) Visible = true; });              // Excel 还原 → 显示
}
```

### 2.3 关键点（务必注意）

- **`WINEVENT_OUTOFCONTEXT`**：回调在非托管上下文执行，不能在回调里直接操作 WinForms 控件，必须 `PostToUi`（内部 `BeginInvoke`）切回 UI 线程。
- **`WINEVENT_SKIPOWNPROCESS`**：避免收到本进程自身窗口的事件，减少无关触发。
- **`idObject == 0`**：只处理窗口对象（OBJID_WINDOW），忽略子控件事件。
- **`ExcelDnaUtil.WindowHandle`** 取的是 Excel 主窗口 HWND；按 `pid` 过滤事件，确保只响应本 Excel 实例。
- 窗口关闭时务必 `UnhookWinEvent(_winEventHook)`，否则钩子悬空可能导致崩溃（见 `FormClosing`）。
- `PostToUi` 中要判断 `!IsDisposed`，防止窗口已释放后访问控件。
- 由于本窗口不再“拥有”于 Excel，Excel 最小化时它**不会**自动隐藏，必须靠 `MINIMIZESTART` 事件手动 `Visible = false`；反之还原时由 `MINIMIZEEND` 恢复。

## 3. 窗口阻塞问题分析

### 3.1 旧实现为何会阻塞

早期（也是 v2.9.2 及之前）的打开逻辑：

```csharp
IntPtr owner = ExcelDnaUtil.WindowHandle;
form.Show(new Win32Window(owner));   // 以 Excel 为“拥有窗口”
```

`Form.Show(owner)` 会让 WinForms 把本窗口登记为 Excel 主窗口的 **拥有窗口（owned window）**。拥有窗口与父窗口的关系带来两个副作用：

1. **任务栏交互被“咬住”**：Excel 主窗口与拥有窗口在任务栏上关联。在任务栏单击 Excel 试图最小化时，系统会优先处理拥有窗口的焦点/层级，导致 Excel 的最小化/还原被多维表窗口“挡住”，必须先把多维表窗口最小化或关闭，才能操作 Excel 任务栏。
2. **焦点争夺**：拥有窗口始终保持于父窗口之上，用户点 Excel 区域时焦点容易被抢回。

这正是用户反馈的“在状态栏单击 Excel 时就无法隐藏切换了，会被多维表窗口阻塞”。

### 3.2 解决方案

把“拥有窗口”改为“无拥有窗口 + 事件跟随”：

```csharp
// RibbonController.OnOpenMultiTable
var form = new HtmlMainForm();
form.Show();   // 不带 owner，不再阻塞 Excel 任务栏
```

- 不再登记为拥有窗口 → 任务栏单击 Excel 可正常最小化/还原，不再被阻塞。
- 由第 2 节的 WinEvent 钩子负责“随 Excel 最小化一起隐藏”，把失去的体验补回来。
- `ShowInTaskbar = false` 让它在任务栏不单独占坑，视觉上仍是“Excel 的面板”。

> 注意：旧实现里“未关窗口时打开 Excel 会强制显示在 Excel 前面”的现象，根因也是拥有窗口的强制层级。改为无拥有窗口后，本窗口仅在**刚打开的瞬间**通过 `Load` 事件里的短暂 `TopMost` 确保可见（见第 4 节），之后不再强制置前，避免了“强插到 Excel 前面”的突兀感。

## 4. 强制置顶功能的实现与介绍

### 4.1 打开瞬间的短暂置顶（确保可见）

在 `HtmlMainForm` 构造函数 `Load` 事件中，用极短的“置顶→取消”让窗口在打开时一定显示到最前，但**不长期霸占**置顶：

```csharp
Load += (s, e) =>
{
    try { TopMost = true; BringToFront(); Activate(); TopMost = false; }
    catch { }
};
```

这是一次性行为，打开完成后即恢复为普通窗口层级。

### 4.2 用户可切换的“窗口置顶”

设置面板（HTML 右上角“设置”）提供**“窗口置顶”**复选框，状态保存在浏览器 `localStorage`（键 `mt_app_settings`）。勾选后通过桥接调用 C# 的 `setTopMost`：

```javascript
// index.html
api.call('setTopMost', { value: APP_SETTINGS.topMost });
```

```csharp
// HtmlMainForm.cs
private object SetTopMost(JsonElement pars)
{
    bool v = ...;
    PostToUi(() => { try { TopMost = v; } catch { } });
    return new { ok = true, topMost = v };
}
```

- `TopMost = true` 时窗口始终盖在最上层（包括 Excel 之上），适合“边看数据边录入”的场景；
- 取消勾选即恢复普通层级，不再遮挡 Excel。

### 4.3 “打开时最大化”开关

同一设置面板还提供**“打开时最大化”**复选框，同样存于 `mt_app_settings`。勾选后，打开窗口时 HTML 会调用桥接 `setOpenMaximized`：

```csharp
private object SetOpenMaximized(JsonElement pars)
{
    bool v = ...;
    PostToUi(() => { try { WindowState = v ? FormWindowState.Maximized : FormWindowState.Normal; } catch { } });
    return new { ok = true, openMaximized = v };
}
```

由于设置会在页面加载时（`loadAppSettings → applyAppSettings`）主动下发一次，因此**每次打开**都会按用户上次的偏好自动最大化或保持正常大小。

## 5. 小结与排错

| 体验 | 实现手段 | 易错点 |
| --- | --- | --- |
| 随 Excel 最小化隐藏 | WinEvent 钩子（MINIMIZE START/END）+ 手动 `Visible` | 回调必须 `PostToUi` 回 UI 线程；关闭时 `UnhookWinEvent` |
| 不阻塞任务栏 | `Show()` 不带 owner + `ShowInTaskbar=false` | 不能再用 `Form.Show(owner)` |
| 打开即显示 | `Load` 中短暂 `TopMost` | 用完立刻复位，避免长期置顶 |
| 用户置顶 | 设置 → `setTopMost` 桥接 | 持久化到 `localStorage` |
| 打开最大化 | 设置 → `setOpenMaximized` 桥接 | 加载时主动下发一次 |

**排错清单**：
- 窗口不再随 Excel 隐藏 → 检查 `ExcelDnaUtil.WindowHandle` 是否为 0（未取到 Excel 主窗口），或 `SetWinEventHook` 返回值是否为 `IntPtr.Zero`（钩子安装失败）。
- 任务栏仍被阻塞 → 确认 `RibbonController.OnOpenMultiTable` 已改为 `form.Show()` 且无任何 `Win32Window` owner。
- 置顶/最大化不生效 → 确认 HTML 的 `applyAppSettings()` 已调用对应桥接，且 C# `Dispatch` 中有 `setTopMost` / `setOpenMaximized` 分支。
- 关闭窗口后 Excel 卡顿或崩溃 → 确认 `FormClosing` 中已 `UnhookWinEvent`。
