# 多维表字段处理优化方案

> 基于 Excel 超级表（ListObject）作为数据源的多维表插件字段识别与处理策略。
> 目标：在自动推断提升效率的同时，通过“建议 + 人工确认”机制避免脏数据丢失。

## 一、核心原则

1. **自动推断仅作建议，不强制生效**
   - 任何自动识别结果都不能直接锁定为字段类型。
   - 必须弹出预览确认界面，由用户最终确认或修改每一列的类型。

2. **安全第一：宁可降级文本，也不强行转换**
   - 一列中只要存在无法解析为数字/日期的文本、空值或错误值，就整体降级为文本。
   - 避免“大部分像数字就识别为数字”导致少量文本数据被清空或丢失。

3. **高级字段不自动识别**
   - 单选、多选、关联、编号、附件等高级字段类型，默认全部识别为文本。
   - 由用户在预览界面手动切换为对应高级类型。

4. **字段类型一旦确定，刷新时禁止自动变更**
   - 首次导入后，后续同步 Excel 数据时只更新单元格值，不重新推断或修改字段类型。
   - 无法转换的数据保留原始文本，UI 标记异常，记录日志，不抛异常崩溃。

## 二、三级推断策略

### 第 1 级：读取超级表元信息（仅作参考）

读取 `ListColumn.ListDataFormat.Type` 作为初始建议：

| ListDataFormat 类型 | 初始建议 |
| --- | --- |
| xlListDataTypeNumber | 数字 |
| xlListDataTypeDate | 日期 |
| xlListDataTypeText | 文本 |

> ⚠️ 注意：即使超级表标记为数字/日期，也必须经过第 2 级真实数据采样校验；发现文本即降级为文本。

### 第 2 级：抽样扫描真实数据

对每一列抽取最多 **200 行有效非空单元格**（读取 `.Value2`，不读公式文本），根据样本修正类型：

| 样本特征 | 推断结果 |
| --- | --- |
| 全部可解析为数字 | 数字 |
| 全部可解析为日期 | 日期 |
| 数字 + 文本混合 / 大量空值 / 错误值 | **强制降级为文本** |
| 布尔、单选、多选、关联、编号 | **固定为文本**（不自动识别） |

性能要求：不要遍历全部行，上万行表格抽样 200 行足够做类型推断。

### 第 3 级：预览确认界面（不可省略）

弹出导入预览窗口，内容至少包含：

- **字段名称**：超级表表头。
- **建议类型**：系统推断后的候选类型。
- **前 5 行样例**：让用户直观判断识别是否异常。
- **类型下拉框**：允许用户手动修改目标字段类型。
- **确认/取消按钮**：确认后才正式生成内部多维数据集。

> 参考飞书 / WPS 多维表导入 Excel 的行为：均提供预览确认环节。

## 三、两种工作模式

### 模式 A：首次导入（新建多维数据集）

1. 获取当前工作表中的 `ListObject` 超级表。
2. 读取表头作为字段名；读取 `ListDataFormat` 作为初始建议。
3. 抽样扫描列真实数据，修正推断类型。
4. 弹出预览界面，用户确认或修改字段类型。
5. 确认后生成插件内部多维数据集。

### 模式 B：后续刷新（同步 Excel 最新数据）

1. **字段类型固定不变**：刷新时禁止重新推断或修改字段类型。
2. 只同步单元格数据。
3. 若单元格无法转换为已有字段类型：
   - 保留原始文本；
   - 在 UI 标记该行该字段格式异常；
   - 记录警告日志；
   - 不抛异常、不崩溃、不丢数据。

## 四、与飞书 / WPS 多维表导入行为对比

| 项目 | 飞书 / WPS 多维表导入 Excel | 本插件（超级表源） |
| --- | --- | --- |
| 自动推断 | 采样推断基础类型 | 采样推断 + 参考 ListDataFormat |
| 高级字段 | 不自动识别 | 不自动识别，默认文本 |
| 是否强制生效 | 导入前预览，可手动修改 | 必须预览确认，自动仅为建议 |
| 脏数据策略 | 降级文本，防止丢失 | 优先降级文本，绝不强行转换 |
| 刷新数据时 | 字段类型固定不变 | 字段类型固定不变 |

## 五、需要规避的典型陷阱

1. **不要信任单元格格式**：Excel 中显示为日期，底层可能是数字序列号；显示为货币，底层可能是数字。必须读 `.Value2` 做真实值判断。
2. **不要读公式文本**：读取公式字符串会导致识别错误，应取计算后的 `.Value2`。
3. **错误值统一当文本**：`#N/A`、`#VALUE!` 等错误单元格统一按文本处理。
4. **不要全表遍历推断**：大表性能差，抽样 200 行足够。
5. **混合列必须降级**：一列中同时存在 `100`、`待补充`、空值时，不能识别为数字。

## 六、可选高级开关

- **“信任超级表格式，跳过预览确认”** 选项，默认关闭。
- 开启后直接使用推断结果生成数据集，适合熟悉源数据的高级用户。
- 默认行为必须保留预览确认，确保数据安全。

## 七、对当前插件的落地建议

1. 在数据源选择/导入流程中增加“字段预览”弹窗。
2. 预览弹窗复用现有字段类型下拉组件（Text / Number / Date / Select / Quarter 等）。
3. 将推断逻辑封装为独立模块：`FieldInferenceEngine`：
   - 输入：`ListObject`
   - 输出：`List<FieldSuggestion>`（含建议类型 + 样例数据）
4. 刷新数据时，`openTable` / 数据同步逻辑不再调用推断模块，仅做数据类型兼容转换。
5. 在 `FieldSchema` 或 `FieldOverride` 中保留 `inferredType` 与 `userType`，便于追踪“系统建议”与“用户最终选择”。

## 八、总结

本方案的核心是 **“建议但不决定、降级但不丢失、固定但不僵化”**：

- 系统负责给出合理的初始字段类型建议；
- 用户拥有最终确认和修改权；
- 脏数据场景优先保护原始内容；
- 字段类型在首次导入后保持稳定，刷新时不自动变更。

按此方案实施后，可显著降低因自动识别错误导致的数据丢失风险，同时保留飞书式的高效导入体验。
