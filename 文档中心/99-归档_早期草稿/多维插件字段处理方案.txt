# 针对【源数据 = Excel 超级表 (ListObject)】多维插件字段处理方案

> 
> 技术栈：Excel‑DNA + .NET8 WPF；读取当前工作表已经存在的超级表，生成你的多维表内部数据集。
> 关键点：**不要直接无脑全自动识别，采用「自动推断给出建议 + 用户确认修改」的模式**，不能直接强制锁定字段类型。

## 背景问题（超级表的坑）

1. Excel 超级表`ListObject`有`ListDataFormat.Type`，但**这个类型只是格式提示，不能信任**Microsoft ...。同一列可以同时存在数字、文本、空单元格、公式结果。
2. Excel 底层存储只有两大类：**数字（日期本质是数字序列号）、文本**，显示格式只是 “马甲”，单元格格式≠真实存储类型。
3. 超级表允许一列混杂：`100`、`待补充`、空值。如果程序自动识别为【数字字段】，`待补充`会直接转换失败，造成数据丢失。
4. 超级表的公式：读取要拿`.Value2`计算后的结果，不要读公式文本。

## 最终方案：三级策略（推荐写进你的 MD 设计文档）

### 1）优先读取超级表本身的元信息（ListColumn.ListDataFormat）

拿超级表列自带的格式作为**初始候选建议**，但只做参考，不作为最终判定。

- xlListDataTypeNumber → 建议【数字】
- xlListDataTypeDate → 建议【日期】
- xlListDataTypeText → 建议【文本】

> 
> ⚠️注意：就算超级表标记为数字，只要扫描样本发现有文本，直接降级为文本。

### 2）抽样扫描本列真实数据，修正推断结果

不要遍历全部行（上万行性能差），抽样：取前 200 行有效非空单元格做样本分析。
规则：

1. 样本全部可解析为数字 → 建议数字字段
2. 样本全部可解析为日期 → 建议日期字段
3. 样本里面混杂数字 + 文字 / 大量空单元格 → **安全降级为文本字段（宁可全部文本，绝不丢数据）**
4. 布尔、单选、多选、关联、编号：**完全不自动识别，强制默认为文本，交给用户手动切换**。

### 3）必须提供预览确认界面（核心，不能省略）

> 
> 飞书 / WPS 多维表导入 Excel 都有这一步。
> 弹出预览窗口：

- 每一列：显示【字段名称】、【系统推断的建议类型】、下拉框允许用户手动修改类型。
- 预览前 5 行样例数据，让用户一眼看到是否识别异常。
- 用户确认之后，才正式生成多维表内部数据集。

> 
> ❌禁止：读取超级表直接自动生成字段，跳过人工确认。
> ✅正确：自动只是给建议，决定权交给用户。

## 两种模式区分

### 模式 A：新建多维数据集，从超级表一次性导入（首次加载）

1. 获取工作表`ListObject`超级表；读取表头作为字段名。
2. 读取`ListDataFormat`拿到超级表列格式。
3. 抽样扫描列真实数据，修正推断字段类型。
4. WPF 弹出预览界面，用户可以修改每一列字段类型。
5. 用户确认，把超级表数据读入插件内部多维数据集。

### 模式 B：后续刷新（同步 Excel 超级表最新数据）

> 
> 这是你插件很关键的场景：Excel 里改超级表，插件多维表同步更新。

1. **字段类型一旦创建完成，刷新时不允许自动变更字段类型！**
2. 只同步单元格数据；如果单元格数据无法转换为已有字段类型，记录警告日志，保留原始文本，不丢弃数据。

> 
> 例：多维内部字段是数字，Excel 超级表单元格填入 “未录入”，不能直接报错崩溃；保存原始字符串，在 UI 标记该行格式异常。

## 和飞书 / WPS 多维表导入行为对比

表格

| 项目 | 飞书 / WPS 多维表导入 Excel | 你的 ExcelDNA 插件（超级表源） |
| --- | --- | --- |
| 自动推断 | ✅采样推断基础类型（数字 / 日期 / 文本） | ✅采样推断，同时参考超级表 ListDataFormat 元信息 |
| 高级字段（单选 / 关联） | ❌不自动识别 | ❌全部默认文本，用户手动切换 |
| 是否强制生效 | ❌导入前预览，可手动改类型 | ❌必须预览确认，自动仅为建议 |
| 混合脏数据策略 | 降级文本，防止丢失 | **优先降级文本，绝不强行转数字 / 日期** |
| 刷新数据时 | 字段类型固定不变，不会自动变化 | 刷新同步数据，**禁止自动修改字段类型** |

## 什么场景可以 “完全自动识别，不弹出确认框”

仅适合：用户明确勾选【信任源超级表格式】的高级选项。

> 
> 作为可选开关，不作为默认行为。默认一定弹出预览确认。

## 写到你的设计文档的片段，可以直接复制

```
# 多维表插件：从Excel超级表(ListObject)导入字段处理模块
## 定位
读取工作表中已存在的超级表，生成插件内部多维数据集；
自动识别仅提供**建议值**，不能直接强制生效，防止脏数据造成数据丢失。

## 输入源
Excel ListObject（超级表），包含表头行 + 数据行。

## 推断流程
1. 读取ListObject.ListColumns，获取表头名称；读取ListDataFormat.Type，获取超级表列格式，作为初始候选类型。
2. 对每一列抽样读取最多200行非空单元格Value2，做真实数据采样校验。
    - 全部样本可转为数字 → 候选：数字
    - 全部样本可转为日期 → 候选：日期
    - 存在文本、混杂格式、大量空值 → 强制降级候选为文本
    - 单选、多选、关联、编号等高级字段：候选固定为文本，不自动推断。
3. 弹出导入预览界面：
    - 展示每列：字段名、推断得到的候选字段类型、前5行样例数据
    - 每列提供下拉框，允许用户手动修改目标字段类型
4. 用户确认后，执行导入，生成内部多维数据集。

## 刷新同步规则（已有数据集，重新读取超级表）
1. **已经定义好的字段类型，刷新数据时禁止自动变更**。
2. 如果Excel单元格内容无法转换为内部字段类型，保留原始文本，记录警告，UI标记异常，不丢弃原始数据，不直接抛出异常崩溃。

## 安全约束
1. 不直接信任Excel超级表自带的ListDataFormat，仅做参考，必须结合真实单元格采样校验。
2. 宁可识别成文本，也不要强行转换数字/日期，避免原始数据丢失。
3. 高级字段类型不做自动识别，全部交由用户手动配置。

## 可选高级开关
增加选项【信任超级表格式，跳过预览确认】，默认为关闭；打开后直接使用推断结果生成数据集，给熟悉数据的高级用户使用。
```

## 开发层面的注意点

1. Excel‑DNA 读取超级表，用`ListObject.ListColumns`，单元格取值使用`.Value2`，不要用`.Value`，避开日期格式干扰。
2. 不要遍历全部行做类型推断，上万行表格会造成 Excel 卡顿，抽样足够。
3. 遇到 Excel 错误单元格`#N/A`、`#VALUE!`，统一当做文本处理。

## 1、关键局限（非常重要，对你本地多维软件开发有参考价值）

1. **只支持基础类型自动识别：文本、数字、日期**；单选、多选、附件、关联、编号这些高级字段**完全不能自动识别，必须手动设置**。
2. 识别是**采样推断**，不是 100% 遍历全部行；数据量大、脏数据多，推断会出错。
3. 自动识别只是**初始建议**，导入弹窗允许你手动修改每一列的字段类型；导入完成之后，随时可以手动切换字段类型。
4. 导入完成后，**后续新增行不会自动改变字段类型**，字段一旦确定，类型固定，不会因为填入新数据自动切换。

## 2、和飞书多维表对比

两者逻辑几乎一致：

- 导入 Excel：自动推断基础字段类型，允许人工修正
- 高级字段（单选、关联）无法自动识别，需要手动配置
- 脏数据、混合内容优先降级为文本，防止数据丢失

## 3、给到你本地多维表软件的设计参考（可以写进你的 MD 文档）

### 方案设计参考

1. **导入本地 Excel/csv 的时候做自动字段推断**：扫描列样本，判断数字 / 日期 / 文本，给出初始字段类型。
2. **绝对不强制锁定推断结果**：导入界面提供预览，允许用户手动修改每一列的目标字段类型。
3. 一旦数据表创建完成，**后续新增记录不能自动变更字段类型**，避免老数据错乱。
4. 遇到混合格式、脏数据：安全策略优先降级为文本，防止数据丢失，不要强行识别数字 / 日期。
5. 单选、多选、关联、编号这类高级字段，**不做自动识别，交给用户手动指定**。

### 需要规避的坑（WPS / 飞书都踩过）

> 
> 如果一列中大部分是数字，少量文本；自动识别成数字，会直接把文本数据清空丢失。
> 本地软件策略：宁可识别成文本，也不要强行转数字，避免原始数据被破坏。
