# 双向联动计算字段：数量‑单价‑金额
## 业务说明
三个字段：数量(数字)、单价(数字)、金额(数字)
逻辑：
金额 = 数量 × 单价
单价 = 金额 ÷ 数量

### 关键约束：必须有一个【受控推导字段】标记
不能三个字段全部开放手动输入又互相计算，会产生循环歧义。
> 设计方案：提供配置项，由用户选择**哪一个字段为自动推导字段（只读，不允许手动编辑）**
三种模式二选一：
模式1：【金额为推导字段】✅最常用
- 用户手动输入：数量、单价
- 金额自动计算，界面禁止直接编辑金额；修改数量/单价，金额同步刷新。

模式2：【单价为推导字段】
- 用户手动输入：数量、金额
- 单价自动计算，界面禁止直接编辑单价；修改数量/金额，单价自动反算。

模式3：全部手动输入（关闭联动）
- 数量、单价、金额全部允许手动录入，不执行自动计算。

> ❌禁止：三个字段同时允许手动输入同时双向计算，会出现逻辑冲突。

## 触发时机
1. 在多维表窗体/详情面板修改字段值，失去焦点、或者回车确认后触发联动。
2. Excel源超级表同步过来的数据：**不执行自动重算**。
> 说明：源Excel已经存在公式计算结果，插件只读取已有值，不覆盖源数据；联动计算仅发生在插件界面内部编辑记录的时候。

## 边界条件
1. 数量 = 0
   除法会除零错误，此时推导字段置空，UI展示提示：“数量不能为0，无法计算”。
2. 任意一个输入字段为空：推导字段置空。
3. 输入非数字文本：标记字段异常，不执行计算。
4. 小数精度：配置可设置保留小数位数（金额一般2位小数），四舍五入。

## 与Excel超级表的交互（你的插件重点）
1. 从Excel超级表导入：数量、单价、金额都是普通数字字段，导入时**不自动开启联动**。
2. 用户在插件中手动开启「双向联动配置」，绑定这三个字段。
3. 在插件UI编辑记录，触发联动计算后，保存回写Excel超级表对应单元格。
4. 如果Excel表格本身写了公式：插件回写会覆盖单元格公式，变成静态数值。
> ⚠️重要提示，UI需要提示用户：开启联动保存回写Excel后，原单元格公式会丢失，转为普通数值。

## UI需要的控件配置（WPF）
1. 在字段设置弹窗，增加【双向联动计算】配置面板
2. 选择：数量字段、单价字段、金额字段（从当前数据集数字字段下拉选择）
3. 单选框选择：推导字段 → 【金额 / 单价 / 关闭联动】
4. 设置金额小数位数。

## 数据存储
在多维数据集元数据中保存配置，不是保存在单条记录：
```json
{
  "enableBidirectionalCalc": true,
  "qtyField":"数量",
  "priceField":"单价",
  "totalField":"金额",
  "deriveField":"total", // total=金额推导，price=单价推导，null关闭
  "decimalPlaces":2
}


## 和市面上多维表对比
1. 飞书多维表：**没有原生双向互算字段**。飞书只支持单向公式字段（只读）。想要双向，只能用脚本自动化。
2. WPS多维表：同样只有单向公式，不支持双向互算；
> 也就是说：**这个双向联动是你插件的增强能力，原生多维表组件本身没有这个能力，需要自己实现业务层逻辑**。

## 开发必要条件清单
1. 数据集内必须存在3个**数字类型字段**（数量、单价、金额），不能是文本。
2. 数据集元数据层，存储这套联动配置。
3. UI层：详情窗体编辑控件，监听控件失去焦点/值变更事件；**推导字段输入框设置IsReadOnly=True，禁止手动输入**。
4. 业务层计算函数：做数字校验、除零保护、小数舍入。
5. 回写Excel时的风险提示：会覆盖原有Excel公式。
6. 同步Excel超级表数据时：只读取，不自动重算，避免把Excel原有数据覆盖。

### 伪代码片段（C#逻辑）
```csharp
// 配置：deriveField = total 代表金额是推导字段
if(config.EnableBidirectionalCalc && config.DeriveField == "total")
{
    decimal qty = GetFieldDecimal(row, config.QtyField);
    decimal price = GetFieldDecimal(row, config.PriceField);
    decimal total = qty * price;
    SetFieldValue(row, config.TotalField, Math.Round(total, config.DecimalPlaces));
}
// deriveField = price，单价为推导字段
else if(config.DeriveField == "price")
{
    decimal qty = GetFieldDecimal(row, config.QtyField);
    decimal total = GetFieldDecimal(row, config.TotalField);
    if(qty == 0)
    {
        SetFieldValue(row, config.PriceField, null);
        ShowWarning("数量不能为0，无法计算单价");
    }
    else
    {
        decimal price = total / qty;
        SetFieldValue(row, config.PriceField, Math.Round(price, config.DecimalPlaces));
    }
}


# 双向联动计算字段：性能瓶颈、隐性问题与冲突
## 性能限值
1. 单条记录编辑场景：仅操作当前行，性能无压力，不受总数据集行数影响。
2. 批量修改多条记录：每一条记录都会执行计算逻辑，上万条批量更新会产生CPU开销；叠加Excel回写会进一步卡顿。
3. 禁止行为：**数据刷新、导入、从Excel同步数据时，禁止自动全表执行联动重算**，会造成卡顿，还会篡改源数据。
4. 批量重算能力：提供手动按钮【全部记录重算联动值】，由用户主动触发，不作为自动流程。

## 隐性业务问题
1. 联动仅在插件WPF编辑窗体触发；直接修改Excel源超级表，不会执行联动，会出现「数量/单价/金额」三者数值互相矛盾。
    - 解决方案：提供数据校验工具，扫描全表，标记出计算不匹配的异常行。
2. 小数舍入误差：反复编辑保存，会出现数值来回跳动；严格按配置小数位执行Round。
3. 除零、空值、非数字脏数据，会造成推导字段为空，需要完整容错，避免窗体崩溃。
4. 舍入带来业务分歧：除法反算得到无限小数，保留位数后再次运算，前后结果不一致，需要在文档说明风险。

## 模块冲突
1. 与Excel超级表冲突
    - 插件保存回写Excel，会覆盖原有单元格公式，替换为静态数值；配置界面和保存弹窗必须提示该风险。
    - Excel直接修改源数据，不会触发联动计算。
2. 和普通单向公式字段互斥
    - 参与双向联动的三个字段（数量、单价、金额），不允许再设置为普通公式字段，两套计算逻辑会互相覆盖。配置UI增加互斥校验。
3. 批量导入/粘贴
    - 批量导入不会自动执行联动，导入后数据可能不一致，需要用户手动执行全表重算。
4. 编辑窗体撤销逻辑
    - 撤销操作必须快照保存全部3个联动字段的值，不能只保存用户修改的单个字段，否则会数据不一致。

## 边界约束
1. 联动属于UI层业务逻辑，**不是底层数据约束**，底层数据集本身不会自动保证数量×单价=金额。
2. 联动配置是数据集全局配置，不支持部分行开启、部分行关闭。
3. 推导字段在UI设置只读，但是底层内存模型仍然允许写，代码层面要防止绕过UI直接修改推导字段。
