# WPF 日历视图：任务条**左右拖拽拉伸（修改开始 / 结束日期，拉长缩短周期）**开源参考

> 
> 说明：**HandyControl 原生 Calendar 控件只有日期选择，完全没有 “任务条拖拽拉伸 resize” 能力**，这就是你卡住的根源。
> 飞书 / WPS 多维表日历视图，本质是**月历网格 + 可拉伸任务矩形（Canvas 自定义绘制）**，不是系统 Calendar 控件。

## 一、可直接参考的开源 WPF 项目（具备任务左右拉伸 resize）

### 1、GanttWPF（GitHub，MIT，重点参考）GitHub

`https://github.com/garakutanokiseki/GanttWPF`

- 原 codeplex 迁移过来，WPF 原生，支持：
  - 任务条**左右边缘拖拽拉伸，修改 Start/End 日期**（就是你要的横向调整周期）
  - 整体拖动任务条平移
  - Canvas 底层实现，没有重度第三方依赖
- 可以把它内部的**拖拽 resize 逻辑、鼠标坐标↔日期换算**单独抠出来，移植到你的日历视图。

> 
> 注意：它是甘特组件，不是日历月视图，但是**拖拽拉伸的核心算法完全通用**。

### 2、Wpf‑TimelineControl（MIT）GitHub

`https://github.com/llane12/wpf‑timeline`

- 时间轴控件，支持任务条左右拉伸改变起止时间；.NET8 兼容。
- 适合学习：鼠标 Down/Move/Up，计算偏移，把像素偏移翻译成日期增量。

### 3、Gong‑Solutions.WPF.DragDrop（拖拽底层库，必看）

`https://github.com/punker76/gong‑wpf‑dragdrop`

> 
> ⚠️这个库**只做拖动移动，默认不支持 “边缘拉伸 resize”**，只能做任务整体拖动。
> 但是它的 Mouse 事件、装饰器 Adorner 实现，可以拿来做你自己的 Resize 拖拽。
> 很多人踩坑：直接用这个库，想实现左右拉伸缩，做不出来，因为库本身没有 resize 逻辑。

> 
> 重点：**任务条左右拉伸，不属于普通 DragDrop，是「拖拽调整控件大小」，需要自己捕获鼠标 Hit 测试左右边缘**。

## 二、日历视图（月视图）任务拉伸，核心难点（你大概率卡在这里）

> 
> 日历视图和甘特视图不一样：甘特是横向连续时间轴；**日历是网格，任务会跨多个单元格（跨多天）**。

1. **命中检测：鼠标什么时候是拉伸左边缘、拉伸右边缘，还是拖动整个任务**
   - 鼠标靠近任务条**左侧 5‑8 像素**：光标变成左右箭头，拖拽 = 修改开始日期
   - 鼠标靠近任务条**右侧 5‑8 像素**：光标变成左右箭头，拖拽 = 修改结束日期
   - 中间区域：拖动整体移动任务

> 
> 很多实现失败：分不清 “拖动整体” 和 “拉伸边缘”，一拉就整体跑，不会拉长周期。

2. **鼠标屏幕像素 → 日历网格日期的转换（最容易出错）**

- 获取鼠标相对于整个日历画布的 X/Y；
- 判断鼠标落在**哪一个日历单元格（哪一天）**；
- 拖拽过程，把鼠标位置翻译成新的`StartDate` / `EndDate`；

> 
> 坑：滚动条、ScrollViewer 偏移，必须把`e.GetPosition()`减去 ScrollViewer 的`HorizontalOffset`，否则坐标全部错位。

3. **跨多天任务的布局刷新**
拉伸之后任务跨的天数变了，要重新计算任务条在月历网格中的行、列、跨列数量，重新 Arrange 布局。
4. **边界保护：不能让结束日期早于开始日期**

## 三、两种实现路线给你选择

### 路线 A：参考 GanttWPF 里面的 Resize 逻辑，移植到你的日历月视图（推荐）

GanttWPF 关键源码文件：
`GanttBar.cs`：任务条，处理 MouseDown、MouseMove、MouseUp，区分左边缘拉伸、右边缘拉伸、整体拖动。

> 
> 你不需要完整引入整个甘特控件，把**鼠标命中边缘判断、像素转时间、更新起止日期这一套逻辑复制改写到你的日历任务条 UserControl**。

核心伪代码（参考 GanttWPF 逻辑）

```
// MouseDown：判断点击的是左边缘、右边缘，还是任务主体
var pt = e.GetPosition(this);
if (pt.X < 8)
{
    _resizeMode = ResizeMode.LeftEdge; // 修改开始日期
}
else if (pt.X > ActualWidth‑8)
{
    _resizeMode = ResizeMode.RightEdge; // 修改结束日期
}
else
{
    _resizeMode = ResizeMode.Move; //整体移动
}

// MouseMove：根据鼠标偏移，换算出新的日期
if(_resizeMode == LeftEdge)
{
    //鼠标X偏移 → 换算成新的StartDate
    var newStart = PixelToDate(mouseX);
    TaskItem.StartDate = newStart;
}
else if(_resizeMode == RightEdge)
{
    var newEnd = PixelToDate(mouseX);
    TaskItem.EndDate = newEnd;
}
//触发UI重新布局
```

> 
> 最大坑：`PixelToDate()`函数，在日历网格中，要把鼠标 X 坐标，减掉 ScrollViewer 横向滚动偏移量，再映射到对应日期。很多人忘记减去`ScrollViewer.HorizontalOffset`，拖拽的时候坐标完全错乱。

### 路线 B：第三方商业控件（不适合你，要授权）

Syncfusion、ComponentOne 有日历调度控件，开箱支持任务拉伸，但闭源付费，不方便和你的 Excel‑DNA 多维表深度融合。

## 四、重要提醒：HandyControl 现状

HandyControl 自带 Calendar 控件**仅用于日期选择弹窗**，没有任务条、没有 resize 拉伸能力，网上博客说 “日历视图支持拖拽调整”，是作者自己手写的自定义 Panel，不是控件自带能力。

## 五、排查你现在实现不了的高频坑清单

1. ❌直接使用 Gong‑DragDrop 库，试图实现拉伸 resize：该库只做整体拖动，没有边缘拉伸逻辑。
2. ❌计算鼠标坐标时，没有减去外层`ScrollViewer.HorizontalOffset`，坐标偏移，拖拽完全不对。
3. ❌分不清三种模式：左边缘拉伸、右边缘拉伸、整体移动，鼠标点击永远进入移动模式。
4. ❌日历网格布局没有做`PixelToDate`转换，直接拿像素宽度去加减，没有映射成真实日期。
5. ❌跨多天任务，修改起止日期之后，没有重新执行布局 Arrange，UI 视觉不更新。

## 简短总结

1. 不要指望 HandyControl 原生 Calendar 做这个；月历日历视图的任务拉伸属于完全自定义交互。
2. **GanttWPF 开源项目，它的任务条 Resize 逻辑是最好的参考样本**，把鼠标事件、边缘命中、像素‑日期映射抠出来移植到你的日历任务条上即可。
3. 核心难点不是拖拽本身，是：区分边缘 / 整体 + ScrollViewer 坐标修正 + 像素与日期互相换算。
