## 第九轮：HTML 窗体"一直停留在正在加载中"（WebView2 桥接死锁，根因级）
- **现象**：用户打开多维表窗口后页面空白、永远卡在"正在加载…"，数据不出来。
- **根因（关键、可复用）**：`HtmlMainForm.OnWebMessage` 在 `CoreWebView2.WebMessageReceived` 回调里**直接同步调用 `ExcelAdapter` 访问 Excel 对象模型**。`WebMessageReceived` 虽在主线程触发，但属于"非宏上下文"；Excel 的 COM 重入保护会把这种"非宏上下文发起的同步对象模型调用"挂起（等待当前调用栈清空），而当前调用栈正卡在等待这次 COM 返回 → **主线程 COM 重入死锁**。C# 端永不回消息 → JS 的 `listTables` promise 永远 pending → 页面永远"正在加载"。
  - 为什么没报"加载失败"而是"一直加载"：异常会被 catch 并回错误；只有"挂起/死锁"才会导致 JS 无限 pending。这恰好印证了死锁而非异常。
  - 参考用的 `WebTaskPaneWpfView` 只做网页导航、从不反向访问 Excel，所以一直没暴露这个坑。
- **修复（C# 端）**：把 `OnWebMessage` 中的 Excel 访问用 **`ExcelDna.Integration.ExcelAsyncUtil.QueueAsMacro(Action)`** 包裹——把操作排到 Excel 的宏上下文执行，`WebMessageReceived` 立即返回、不再阻塞主线程，彻底消除死锁。注意 `JsonElement` 生命周期依赖 `JsonDocument`（using 内），须在 QueueAsMacro 之前把 `params` 提取为原始 JSON 字符串（`GetRawText()`），在宏回调内重新 `JsonDocument.Parse` 再交给 `Dispatch`。回传结果仍在宏回调里用 `PostWebMessageAsJson`（线程安全，任意线程可调用）。
- **加固（JS 端 index.html）**：① `api.call` 增加 20s 超时，超时给出明确提示（含"确认 Excel 已打开含超级表的工作簿 / 完全关闭旧 Excel 重装 / 已装 WebView2 Runtime"）；② 启动时轮询等待 `window.chrome.webview` 就绪（最多 15s），避免"桥接未就绪"的瞬间 reject；③ 加载/通信失败显示"⚠️ + 原因 + 重试按钮"，不再无限"正在加载中"。
- **验证**：`dotnet build -c Release` 与 `build_addin.ps1 -Configuration Release` 均 0 错误；`dist/files/MultiTableAddin.dll` = 481280 字节 / 18:36，与 `src/bin/Release` 一致；内嵌资源 `MultiTableAddin.Html.index` 已打入。
- **交付须知（用户侧）**：必须**完全关闭 Excel/WPS（含后台进程）**后重跑 `install_excel_addin.bat`/`install_wps_addin.bat` 才能加载新 DLL。若仍异常，看日志 `AddInRuntime.GetAddInDirectory()/logs/yyyy-MM-dd.log`：有 `HtmlMainForm.Message.Received` 但无 `HtmlMainForm.Message.Dispatched` = QueueAsMacro 未执行（Excel 未处于可宏上下文，需确认 Excel 交互空闲）；有 `Dispatched` 但页面仍空 = 回传失败。
- **经验**：Excel-DNA 中，从 WebView2/定时器/UI 回调等非宏上下文访问 Excel 对象模型，一律走 `ExcelAsyncUtil.QueueAsMacro`，否则必现重入死锁。

## 第十轮：仍空白 + "加编译时间确认版本"（版本自检 + 诊断增强）

## 第十一轮：仍空白——C# 已执行但回传消息被吞（QueueAsMacro 里直接 PostWebMessage 导致消息泵阻塞）
- **现象**：用户截图显示页面报"加载失败：与 C# 通信超时（20s）"；诊断行显示`桥接就绪=true`，但`getAppInfo=err:...`、`listTables=err:...`；构建时间未知（因 `Assembly.Location` 在 Excel-DNA 上下文常为空）。
- **日志铁证**：`HtmlMainForm.Message.Received` → `Queued` → `Dispatched` 均出现，`ExcelAdapter.GetTableSources` 也找到了表。说明 C# 端**完整执行了 Excel 访问**，但 JS 没收到回传 → `PostWebMessageAsJson` 在宏上下文调用时被静默吞掉。
- **根因**：`QueueAsMacro` 把 Excel 访问放到 Excel 宏上下文执行是对的，但**回传 WebView2 消息不能继续在宏上下文直接调用**。宏执行期间 WinForms/WebView2 消息泵被阻塞/处于特殊状态，`PostWebMessageAsJson` 虽然本身线程安全，但消息无法被 JS 层及时接收（或根本没有投递到页面），导致 JS 端永远 pending 超时。
- **修复**：在 `HtmlMainForm` 构造函数中捕获 `SynchronizationContext.Current`（WinForms UI 上下文）。`QueueAsMacro` 回调里执行完 Excel 操作后，通过 `_uiContext.Post(...)` 把 `Send(...)` 切回 UI 上下文执行；同时在 `Send` 成功/失败都写日志（`HtmlMainForm.Message.Sent` / `HtmlMainForm.Send.Error`）。
- **附加修复**：`Assembly.GetExecutingAssembly().Location` 在 Excel-DNA 中常返回空字符串，导致构建时间/路径未知。新增 `GetDllPath()` 后备逻辑：先 `Location`；空则用 `AppDomain.CurrentDomain.BaseDirectory + 程序集名.dll`；再空则用 `Assembly.CodeBase`（file:///）转本地路径。`BuildInfo`/`LoadEmbeddedHtml`/`Init.Ok` 日志/`GetAppInfo` 均改用 `GetDllPath()`。
- **验证**：`build_addin.ps1 -Configuration Release` 0 错误；`dist/files/MultiTableAddin.dll` = 487424 字节 / 19:10:56，与 `src/bin/Release` 完全一致；内嵌资源 `MultiTableAddin.Html.index` 与 `window.__mtBuild` 注入均存在；无 Office 进程。
- **交付要点**：① 完全关闭 Excel/WPS 后台进程；② 重跑 `install_excel_addin.bat`；③ 打开后先看加载页底部"构建时间"，本次应为 19:10 左右；④ 若仍超时，看日志是否出现 `HtmlMainForm.Message.Sent`——无 Sent 说明 UI 上下文回传仍失败；有 Sent 但 JS 超时，看页面诊断行的 `lastMsgId`/`lastMsgError` 判断 JS 是否收到/解析消息。

## 第十二轮：C# 已 Sent，但 JS 端 JSON 解析失败（WebView2 事件 data 直接是对象）
- **现象**：用户截图时间正确（19:10:56），但仍报"与 C# 通信超时（20s）"；诊断行 `lastMsgError=JSON解析失败:"[object Object]" is not valid JSON`。
