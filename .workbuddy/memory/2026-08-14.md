## 续批：#379（仪表盘导出图片仍被截断——根因修复）

### 根因（关键）
- 用户实测 2.9.9 复制/导出的图片右侧图表仍被截一半。**真因不是裁剪坐标算错，而是截图源本身只有视口内容**：`CapturePreviewAsync(Png)` 只截取 WebView2 **当前可见视口**，而仪表盘 `.dash-wrap` 是 `overflow:auto` 滚动容器，超出视口（右侧/底部）的图表根本不在 bitmap 里。
- #375 把 crop 算成 scrollWidth/scrollHeight 让 crop 比视口大，但 C# 第 421–424 行把 crop `Math.Min` clamp 回视口 bitmap 尺寸 → 超出部分直接被砍 → 右侧/底部图表缺失。
- 结论：**只改 JS 裁剪坐标是治标，必须改截图方式为「整页截图」才能治本。**

### 修法（#379）
- JS（`index.html`）：新增 `window.__unlockDash()` / `__relockDash()`，导出前临时把 `.dash-wrap` 与 `#content` 的 `height/overflow` 解锁（`auto`/`visible`），使完整内容进入文档流；导出后还原。
- C#（`HtmlMainForm.cs` `ExportDashboard`）：截图改为 **CDP `Page.captureScreenshot` + `captureBeyondViewport:true` + `fromSurface:true` + `clip`**，由 `clip:{x,y,width,height,scale}` 在整页坐标空间直接裁出仪表盘区域（scale 取 `window.devicePixelRatio` 保证清晰度）。导出前 `ExecuteScript(__unlockDash)`、导出后 `finally` 中 `ExecuteScript(__relockDash)`。
- 保留 `CapturePreviewAsync`+`Bitmap.Clone` 作**兜底**（CDP 异常时回退，保证不崩）。
- 版本升 2.9.10 / FullCapture（Models.cs + verify-build + 两份文档）；DLL 775680 字节。

### 验证（全绿）
- `node check-js-syntax.js` OK；`dotnet build -c Release` 0 错误；拷贝 DLL；`python verify-build.py` exit 0，含 `OK #379 full-page capture via CDP captureBeyondViewport`、`OK #379 C# calls CDP Page.captureScreenshot`、`OK #379 JS unlock dashboard for full capture`、`OK #379 JS relock dashboard after capture`。

### 可沉淀经验
- **WebView2 整页截图必须用 CDP `Page.captureScreenshot(captureBeyondViewport:true)`**，而非 `CapturePreviewAsync`（仅视口）。内部 `overflow:auto` 容器需在截图前解锁让其内容进入文档流，否则 captureBeyondViewport 也只扩到文档尺寸、内部滚动区仍被裁。
- 该经验可补进 MEMORY.md 的 verify-build/构建节，作为 WebView2 截图铁律。
