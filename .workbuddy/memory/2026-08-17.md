### #421 月视图手柄类名冲突 + 按天吸附（关键根因修复）
- **根因（此前 #416/#418/#419/#420 四轮都没触达的底层原因）**：月视图左右手柄 `div` 同时带 `.cal-event-resize` **基类**，而该基类（日视图纵向拖拽条，index.html 第 198 行）有 `left:0;right:0;bottom:0;height:6px`——把 12px 宽的左右柄**撑成覆盖整个任务块的全宽深蓝长条**；左右两柄重叠 → 用户看到「一块长条 + 一个向右标识、且只有一个」；拖拽时全宽蓝条盖住整块 → 视觉上「整列跟着调整」。这是「只有一块、拖拽范围错」的真正来源。
- **修复（三管齐下）**：
  1. **去基类**：手柄 `div` 仅用 `cal-event-resize-l`/`-r` 类名（去掉 `.cal-event-resize` 基类），12px 宽、两端各一、`left:0`/`right:0` 互不影响 → 真正「两个独立控件」。
  2. **中性握把**：`⟨`/`⟩`（U+27E8/27E9）字体无字形时渲染成蓝色方块/方向歧义 → 改为 CSS `::before` **白色双竖纹**（`width:2px;box-shadow:3px 0 0` 同色），方向中性、字体无关；`background:var(--accent)` 实心深蓝条保持不变。
  3. **按天吸附**：`onMove` 彻底弃用自由像素 `origW+dx`，改为 `daysX=Math.round(dx/cellW)`（横向按天）、`wk=Math.round(dy/cellH)`（纵向按整周）、`dd=daysX+7*wk`；平移 `translate(daysX*cellW, wk*cellH)`、拉伸 `width=Math.max(cellW, origW±dd*cellW)`（右缘锚定右边缘、左缘锚定右边缘并 `translateX`）。步长严格 = 一个方格 = 一天。
  - 拖拽守卫 `makeMonthEventDraggable` 由 `classList.contains('cal-event-resize')` 改为 `e.target.closest('.cal-event-resize-l,.cal-event-resize-r')`，与新类名对齐；`onUp` 仍按整格 `Math.round` 写回，与吸附视觉一致。

### 可复用经验（重要）
- **CSS 类名冲突是「仿控件」最隐蔽的坑**：当新控件复用既有基类（哪怕只借用一个属性）时，基类的 `position/left/right/width` 会悄悄撑爆新控件。新控件命名应**完全独立**（不共享基类），或与基类 `@media` 隔离。本例四轮都没查 CSS 基类，直到读真实源码 198 行才定位。
- **握把字符务必 `::before`/`::after` CSS 绘制，不要用 `⟨⟩`/`«»` 等非常用 Unicode 字符**——缺字体会渲染成方块/方向歧义，且不同机器表现不一。
- **拖拽吸附步长 = 网格单元**（月视图 = 列宽 = 天），用 `Math.round(dx/cellW)` 而非自由像素，避免"整列乱动"与"无对齐"。
- verify-build 删除/重建功能后，**旧正向检查要同步迁移为 negative_checks**，否则持续误报 FAIL（本次 5 条即此情况）。
