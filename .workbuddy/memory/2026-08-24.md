## 分析主界面最小化浮窗 + 编写窗口模式 MD 文档

用户反馈：多维表插件窗口最小化时，屏幕左下角（状态栏上方）出现一个很小的窗口，右上角有还原/最大化/关闭三个按钮，但该窗口不在 Excel 之上。要求分析其特性/实现/结构并写 MD，另介绍其它窗口模式。

### 根因（代码实证）
- 主窗口 `HtmlMainForm : Form`（WinForms）经 `RibbonController.OnOpenMultiTable` 以 `form.Show()`（**无 owner**）弹出，`ShowInTaskbar=false`、`WindowState=Maximized`、`TopMost` 默认 false（仅 Load 时短暂 true 后复位）。
- 该“小窗口”即 `HtmlMainForm` **自身最小化态的停靠残影**：无任务栏按钮、无拥有窗口的顶层窗口被最小化时，Windows 停靠到屏幕左下角。
- “不在 Excel 上”：`TopMost=false`；置顶按钮走前台钩子仅对 Excel 前台生效（切其它程序即取消）。
- “跟随 Excel 最小化”：`AttachExcelMinimizeFollow` 挂 Excel 的 `EVENT_SYSTEM_MINIMIZESTART/END` 钩子切换 `Visible`；但该钩子只监听 Excel 句柄，不监听本窗口自身最小化 —— 两条路径独立。

### 其它窗口模式（文档已覆盖）
- A 顶层浮动窗（当前主模式）= HtmlMainForm；B CTP 停靠（DockPosition=Right，Excel 拥有）；C WPF 承载对话框（FormBlankForWpf + DemoWindowService，ShowDialog 模态 / Show 非模态，owner=Excel）；D 标准对话框；E 历史原生 WPF 视图（已废弃）。
- 选型理由：模式 A 不拥有 Excel，故不阻塞 Excel 任务栏最小化/切换，左下角小窗是刻意权衡的副作用。
