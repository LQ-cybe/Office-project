## 一、项目概述

**目标**：开发一款以 Excel/WPS 为宿主的「多维表」分析插件，把本地工作簿中的超级表（ListObject）变成可多视图浏览与编辑的分析工具。

**核心设计原则**：**源文件权威 + 视图配置分离 + 视图层只读变换**。
- 数据永远以 `.xlsx` 中的超级表为准，插件不复制数据；
- 视图配置（字段显隐、分组、排序、筛选、图表定义等）保存在与文件同名的 `.multiview.json` 中，随文件迁移；
- 软件级偏好（窗口置顶、主题、月视图任务数等）保存在浏览器 `localStorage`（`mt_app_settings`），跟随本机。

**支持宿主**：Microsoft Excel（Office16 / EXCEL.EXE）、WPS 表格（et.exe，经 `ExcelDnaUtil.IsET` 识别）。

**数据视图**：表格、表单、看板、画册、日历、甘特、仪表盘、图表（共 8 种）。

## 五、关键工程决策与踩坑记录

1. **WPF/WinForms 类型歧义**：项目同时引用 WPF 与 WinForms，`Rectangle`/`Color` 默认解析到 WPF 类型，编译报 CS1729/CS1503。统一用 `System.Drawing.Rectangle`、`System.Drawing.Color.White` 等全限定名解决（导出裁剪代码必须如此）。
2. **构建 ≠ 交付**：`dotnet build` 只输出到 `src/.../bin/Release/net8.0-windows/`；安装脚本从 `dist/files/` 取 `.xll`+dll。**只 build 不重拷 dist，重装仍加载旧资源**。固定两步：`dotnet build -c Release` → 拷贝 DLL 到 `dist/files/`（覆盖前先 `rm -f` 避免句柄锁 `Permission denied`）。
3. **`verify-build.py` 编码规则**：DLL 内 C# 字符串字面量以 **UTF-16LE** 存储，内嵌 HTML/JS 字符串以 **UTF-8** 存储。校验串必须按对应编码搜索；**注释/源码片段不进 DLL**，不能用作校验串。每次改 `index.html` 后必须同步更新校验串。
4. **无第三方 PDF 库（已移除）**：曾手写最小 PDF（Catalog/Pages/Page/XObject Image + Contents stream），图像用 DeviceRGB + `/Filter /FlateDecode /DecodeParms << /Predictor 15 ... >>`，zlib 由 `System.IO.Compression.ZLibStream` 生成；先铺白底转 24bit RGB 避免透明变黑；1px=1pt。**#376 该功能因位图为栅格（非矢量）依需求移除**，导出仅保留图片(PNG)与剪贴板；导出裁剪仍用 `System.Drawing` 全限定名。
5. **WebView2 截图坐标映射**：`CapturePreviewAsync` 整页截图，需用 `_webView.ClientSize` 比例把视口坐标映射到 Bitmap 像素坐标再 `Bitmap.Clone(Rectangle,...)` 裁剪。**#379 已改为 CDP `Page.captureScreenshot(captureBeyondViewport:true)` 整页截图 + `clip` 直接裁图**，绕过视口限制（旧 `CapturePreviewAsync` 仅截可见区域，滚动外的图表会缺失，导致导出/复制图片右侧或底部被截断）。
6. **图标 SVG 提取坑**：批量去 `width/height` 时若正则写成 `width="..."` 会误伤 `stroke-width`，必须带前导空白锚定（`\swidth="..."`）。

### 用户新问题（任务=项目，同一含义）
